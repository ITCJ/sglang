# Domain Docs

Use a single-context layout: root `CONTEXT.md` for the glossary and
`docs/adr/` for architecture decisions.

Before exploring an area, read `CONTEXT.md` and relevant ADRs when they
exist. Follow the glossary's terms in issues, proposals, and tests.
Surface conflicts with existing ADRs explicitly.

Missing files need no setup action. Create a glossary or ADR when a
domain term or design decision is actually resolved.
