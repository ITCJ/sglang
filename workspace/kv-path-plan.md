# KV 路径初步实验

## 目的

在 Ascend A3 超节点内比较 L2→L1、L3→L2→L1、L3→L1 的 KV 装载成本，
为后续 prefix cache 管理设计提供依据。先测数据路径，不加入模型计算、
prefix 查找、淘汰和请求调度；不将结果直接表述为完整 HiCache 的性能。

## 环境与固定配置

- 同一超节点内两台机器：第一台提供一个目标 NPU 和本地 Host L2，第二台提供 Host L3。
- 使用 Fabric 路径；实际接口能力、物理路径与版本需要记录，不以 TCP 替代正式测量。
- 采用 DeepSeek V3.1、BF16 MLA 的实际 KV 维度与层数。
- L1 固定为当前 Ascend MLA 的原生布局：两个分量分开，各为 `[layer, page, token, 1, dim]`。
- L2 固定为 `page_first_kv_split`：两个分量分开，各为 `[page, layer, token, 1, dim]`。
- L2→L1 复用原有 `kernel_ascend` 搬运实现，不用自行编写的逐页复制替代。
- 第一轮 page size 为 128 tokens，即当前 NPU 未显式指定时的默认值，不宣称为性能最优值。
- 28 的故障与资源状态确认前，不恢复大内存/NPU 测试。

## L3：已有方式全部覆盖

初步实验覆盖当前 MLA 页元数据与 Mooncake 接入代码已有的三种布局来源，不新增按层分组等优化布局。
这里的名称原本是 Host layout 名称，并非 Mooncake 三个独立的 L3 layout 开关。
普通 MLA 接入按逻辑 KV page 生成存储 key，以下区别是对象的数据如何由源内存提供。

| 已有方式 | 当前代码提供给 Mooncake 的数据 | 实验处理 |
| --- | --- | --- |
| `page_first` | 每个逻辑 page 一个覆盖全层数据的连续片段 | 纳入测量 |
| `page_first_direct` | 每个逻辑 page 一个覆盖全层数据的连续片段 | 纳入测量 |
| `layer_first` | 每个逻辑 page 的各层片段，通过 multi-buffer 接口对应同一个 key | 纳入测量 |

三种入口均检查、均覆盖。若实际对象格式和执行路径相同，应记录等价性，
不将它们包装成三个不同的物理 L3 布局。对象内部排列及 Store 分配连续性，
须按远端实际 Mooncake 版本确认；不能从上述名称推断。
其中 `layer_first` 的 multi-buffer 支持已存在于代码，但接入文档将其应用场景列为
HiSparse MLA 等提供 layer-first 元数据的 pool；不能当成当前普通 Ascend MLA 可直接选择的配置。

固定 L2 后，复现这些已有对象组织可能需要适配。必须说明适配范围，
并将读路径中必要的解包、布局转换、暂存成本计入时间。
当前通用页元数据接口未覆盖 Ascend `page_first_kv_split`，相关组合也尚未受支持；
本表是计划覆盖范围，不代表现成可运行配置。写入端的准备与转换成本另行记录。

## 路径与数据量

| 路径 | 含义 |
| --- | --- |
| L2→L1 | 本地 Host 原生布局的 KV 装入目标 NPU，作为本地命中参考 |
| L3→L2→L1 | 远端 KV 装入本地原生 L2，再通过原生搬运接口装入 NPU |
| L3→L1 | 远端 KV 装入最终 NPU 布局，不要求完整落入私有 L2；接口支持待验证 |

两条远端路径都覆盖上表三种已有方式。直接路径若需要暂存、转换或内部中转，
必须记录并计入，不预设能够零中转。无法实现的组合明确记录为不支持，不虚构性能结果。

| 等效上下文长度 | 全层 KV 理论总量 |
| --- | --- |
| 1K | 69 MiB |
| 4K | 275 MiB |
| 16K | 1.07 GiB |
| 64K | 4.29 GiB |
| 128K | 8.58 GiB |

K 按 1024 tokens 计算。理论值来自 `61 × (512 + 64) × 2 = 70,272 Bytes/token`，
实际测试以分配形状和传输字节数为准。先验证小规模正确性，再扩到 128K。

## 访问方式

- 搬运一个完整 prefix 的 KV，不做 sparse token 抽样。
- 分别使用空池分配、经过分配与释放后的 page 序列，体现真实分配器产生的规整与分散情况。
- 三条路径使用相同逻辑数据、相同目标 L1 page 映射，不人为随机打散 baseline。
- 沿用已有对象粒度和批量接口；不强制每页单独提交。记录每次提交的片段数、大小与批量规模。

## 测量与公平性

- 主指标：提交装载至全部 KV 在最终 L1 布局中可用的时间，报告中位数、P95 和有效带宽。
- 同时记录本地暂存内存占用，并逐项校验最终 NPU 数据正确性。
- 分配与注册不计入稳态装载时间，另行记录；运行中的转换、拷贝和同步全部计入。
- 优先复用已有实现及优化。中转路径允许合法的批量、异步和流水，串行版本仅作诊断。
- L3 数据准备不计入读延迟，但记录其转换与写入成本，不将这部分工作隐藏为直接路径的免费收益。
- 固定版本、配置和重复次数，先通过正确性验证，再比较性能。

首轮输出为：本地装载参考，以及两条远端路径在三种已有接入方式、五档数据量和两类分配状态下的结果。
同时报告未支持组合与适配差异，以区分数据布局、搬运实现和缓存层级的影响。
