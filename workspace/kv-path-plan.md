# KV 路径实验

## 任务

编写独立测试脚本，通过 **Mooncake Store + Fabric** 比较三条 KV 搬运路径：

| 路径 | 做什么 |
| --- | --- |
| L2→L1 | 用现有 Ascend 搬运 kernel，把本机 Host KV 搬到 NPU |
| L3→Host staging→L2→L1 | 远端读入额外暂存，再复制到最终 L2，使用同一 kernel 搬到 NPU |
| L3→L2→L1 | 远端直接读入最终 ADXL Host L2，再使用同一 kernel 搬到 NPU |

当前 L3→NPU 直达禁用，分配接口另行调研。`performance_suite.py` 一次运行下述五档容量 × 连续/分散索引 × 三种方式，前置一页冒烟；两端命令见 `kv_path_bench/README.md`。

脚本自己生成测试数据，不加载模型，不执行 prefix 查找和淘汰，不调用 HiCache 的存储适配代码。使用 Mooncake Store；如果接口无法完成某条路径，提供具体错误和复现方法，再讨论方案，不自行绕过 Store。

## 环境与数据

- 同一 Ascend A3 超节点的两台机器：第一台使用一个 NPU 和本地 Host 内存，第二台运行 Mooncake Store。远端测试的 KV 只存第二台。
- 按 DeepSeek V3.1 BF16 MLA 的层数和维度生成数据，不需要模型权重。两个分量为 **512 维压缩 KV、64 维 RoPE 数据**。
- 测试 **1K、4K、16K、64K、128K tokens**，K 为 1024。按 61 层计算，KV 总量约为 69 MiB、275 MiB、1.07 GiB、4.29 GiB、8.58 GiB，记录实际字节数。
- 每个 page 为 **128 tokens**，采用当前 NPU 默认值。
- L1 使用现有 `[layer, page, token, dim]` 布局；L2 使用现有 `page_first_kv_split`，即 `[page, layer, token, dim]`。压缩 KV 和 RoPE 各自存放在独立的缓冲区。

## 对象划分与访问方式

沿用 SGLang 普通 MLA 接入 Mooncake 的划分：**每个 page 存成一个对象，对应一个 key，保存这 128 个 token 在所有层的 KV。** 一次可以批量读取多个对象。

- 五档长度分别对应 **8、32、128、512、1024 个对象**，不把整个 prefix 合成一个大对象。
- 当前性能对象统一为该页全部压缩 KV 后接全部 RoPE，各分量内部按层号、token 排列。保持一页一 key，通过多目标读取直接落入最终 L2，消除非必需的接收暂存和拆分拷贝；有暂存路径使用完全相同的对象作为对照。
- 两条远端路径读取同一组对象，每批读取相同数量。不同对象在 Store 中的地址不保证相邻，不据此构造连续大块读取。
- 当前为串行分批搬运，每批最多 8 页；流水重叠留作后续实验变量。
- 测两种情况：**接收 KV 的 NPU page 地址连续；接收 KV 的 NPU page 索引分散**。当前用确定性非连续索引，尚不模拟分配器长期运行后产生的真实碎片。
- 每种情况下，三条路径都搬同一份数据，写入相同的 NPU 地址。

三种方式统一对象布局、最终 ADXL L2 和目标 L1 映射；与旧交错布局的可行性版本不直接作性能比较。

## 测量与交付

- 每批从发起搬运开始计时，到写入 NPU并同步为止。远端路径包含 Store 读取、有暂存路径包含额外 CPU 拷贝；总样本为各批对应采样之和，不是连续请求端到端耗时。每批独立预热，批次间轮换三种方式的先后顺序。
- 报告 **耗时中位数、P95、有效带宽、本地缓冲区占用**。有效带宽按实际 KV 字节数除以搬运耗时计算。
- 分配内存、注册内存和准备数据不计入搬运耗时；当前记录分配容量，初始化耗时尚未单独采样。
- 检查搬运后的 NPU 数据是否正确，检查时间不计入搬运耗时。预热后重复测量，记录预热和测量次数，各配置保持一致。
- 先跑一页冒烟，再逐步增加到 128K；用户已说明设备可以使用，不再围绕此前机器 down 排查。套件遇错或单配置超时停止，Ctrl+C 只结束其自行启动的客户端进程组。
- 交付：独立脚本目录、简短的两端运行命令、软件版本与参数、每次测量的原始数据和汇总表。

## 新增直达候选：先验证，不纳入性能套件

`fabric_direct_bench/check.py` 独立验证远端 Host DRAM → MemFabric BM SDMA/GH2L → 最终 NPU L1，绕过 Mooncake。保持同一页 KV/RoPE 对象布局，按层分片直接写入最终地址；不改成 NPU→NPU，也不增加接收暂存。先做一页校验，当前只是基于上游代码的候选，尚未远端验证。功能通过、UB 物理链路确认和性能测量分别记录；原有三路径套件保持不变。
