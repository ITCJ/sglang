B

基址容量：源码能力与本票要测的形状

通用 binary-v1 的源、目标基址容量分别来自 Tensor.numel。 容量以 uint64 传给设备核，源码没有 8 或 16 这样的固定小上限。 元数据保存在全局内存，内部两行复制缓冲不限制基址数量。 实际仍受张量容量、内存、int64 索引区间及执行开销约束。

交接已有最多 8→8 的 eager 证据。 已核实的二分路由 Graph 测试容量为 6→6。 另一动态元数据 Graph 测试容量为 3→3。 因此，11 / 12 源和双机池映射的 Graph 能力必须由 26 验证。

两 rank 不会自动让基址数翻倍。 候选页跨多个段时，不能把“两类目标”写成“固定两个基址”。 主 KV、Index K、slot-map 行宽不同，各自建立描述符并分别调用。

26 在 capture 前枚举本 worker 已映射的有关区域。 主 KV 物化预建 12 槽集合；只改变有效任务与页选择，不随请求增加地址。 按 25 后形状测试时，P alive 槽可不产生有效任务。

若后续已有额外副本区域需纳入，容量写作 12 + N_extra_bases。 N_extra_bases 是基础集合之外的独立映射区间数，不是副本页数或副本条目数。 1000 个副本页放在同一连续 arena，仍只增加 1 个基址。 R 沿用计划侧定义，专指 D alive 的副本数，避免与额外基址数混用。

C

两种表的对接与 Graph 合同

kernel 接收的是区域区间表，并不直接理解请求页表。

kernel 参数 形状与语义
src_bases / dst_bases int64[S] / int64[D]，设备可访问的地址
src_ranges / dst_ranges int64[S,2] / int64[D,2]，每个基址的虚拟行区间 [begin,end)
src_base_valid / dst_base_valid bool 或 uint8，区域条目是否有效
src_index / dst_index int64[T]，每条任务的虚拟源行和目标行
valid_mask bool 或 uint8[T]，该任务是否执行
block_bytes / block_dim 本调用固定的行宽与并行配置；行宽上限 32768 B

地址计算为 base + (index - range_begin) * block_bytes。 采用有序、不重叠的固定区间，保持二分路由条件。 所有元数据连续存放；固定容量不足时不能在 replay 中扩表。

当前设备页表是 int64[handle, logical_page]，值为 physical_page。 side / region 隐含在表的字典 key 和 view 中，尚无显式副本列。 26 的适配设计分为三层：

  1. Host 请求页表保存位置描述符列表及版本。
  2. 固定设备缓冲保存候选位置与已选位置。
  3. 图内将已选位置转换为 kernel 的虚拟行索引。

候选位置表达为 (region_slot, physical_page, valid)。 按 [handle, logical_page, location_capacity] 固定预留。 本票至少预留正本与一个副本位置，覆盖 25 的 prefix / D alive 组合。 更大的 location_capacity 由启动时的候选位置上限决定。

未使用的副本条目保持 invalid；验证启用、切换及失效后的回落。 多个候选位置可指向同一 base 槽的不同页，不按页创建基址。 这只是描述符容量预留，不在 26 实施 19 的复制或选择策略。

图内从已选位置读取 region_slot 和 physical_page，生成虚拟行。 沿用当前带层偏移的 view base 时：

index = range_begin[region_slot]
      + physical_page * layers * page_size
      + token_in_page

当前 view base 已含 layer × page_size × row_bytes，不再重复加层偏移。 若某种描述符改用区域首地址，才在行索引中补 layer × page_size。 独立 oracle 必须区分这两种约定。

九张 kernel 元数据、设备页表和目标 HBM 均在 capture 前分配固定存储。 主 KV 写任务预留 2 × N_max 容量；26 生产路径仍只激活原目标。 25 双写再激活第二目标任务，未用任务保持 mask=false。 按调用用途预建读表或写表，不把读源的12槽误用为写目标集合。

图外原位更新页表内容，沿用 binding update event 排序。 图内更新固定任务缓冲的内容；replay 不重新执行 Python 建表逻辑。 映射与 HBM 所有者保活到最后一次使用完成。

保持现有 forward 前版本检查；过期项不能静默变成 mask=false。 不新增每步主机读回或同步。

源码依据见 既有内核研究 与 调用链复核。

远端写：25 的开工条件与 14 的对照

26 的微测同时覆盖远端单目标写与双目标写。 档位为 4K / 32K / 128K tokens 的一层主 KV。 每档包含有 / 无 D 本地读；另测 16 rank 同时写。

16 rank 档记录实际活跃写者、目标共享组和页所有权。 不将重复写同一物理行当作有效聚合带宽。 Index K 另列字节，保持现有单写与原生传输合同。

2026-11-06新版明确按25的副本形状测：每份D副本由对应的一对P rank按页各写一半。 TP16为8份D副本，t=4为2份，t=2为1份；没有D本机复制步骤。 P/D组的t相同。单rank只访问对应D区域，基址容量不乘副本数。

每层聚合远端写字节为R×新算主KV字节，候选页为1×。 候选页保持每页单写者，远端与候选目标分别生成所有权mask。 同一份HBM行不一定在每个rank都具有两个有效目标。 无候选页时候选写为零；Index K只写候选，D侧仍走原生send。

E

读字节与融合后的观测口径

来源按 HBM cache、HBM current、P alive、D alive、prefix 段、副本区域区分。 每条有效物化任务只选择一个来源；无效和 padding 任务不计读字节。 按源字节表示有效任务传输载荷，不冒充硬件总线事务计数。 同请求、同选择、同页表下，迁移前后按源行数及字节必须相等。

当前 token 优先使用 current HBM，DRAM 对应行数恒为 0。 回填只读取已物化的 selected HBM，DRAM 回填重读字节恒为 0。 双目标任务可重复读取 HBM 源，不能用重复 DRAM gather 完成回填。 保留回填和 slot-map 的依赖，不能覆盖尚未被物化读出的缓存行。

迁移前、第一步、第二步使用同一字段集：

字段 统一定义
T_step 同一请求 / step / rank 的现有时间边界；记录时钟域
materialize_ns[layer] copy_ready 到所有有效物化来源完成的设备时间包络
miss_exposed_upper_ns[layer] 默认取 materialize_ns；明确是上界
materialize_wait_ns[layer] 有可靠关联时，主流消费该层结果的实际等待；缺测为 null
source_rows / source_bytes 按上述来源、区域、层统计的有效物化任务行数与载荷
current_dram_rows 必须为 0
refill_dram_bytes 必须为 0；HBM 回填字节单列
copy_launches 物化 / 回填 / slot-map 分别记录，便于解释调用合并
source_time_ns 融合模式为 null，原因 fused；可选分源诊断另表

迁移前 materialize_ns 使用 hit 与 miss 分支完成的包络，不将两路耗时相加。 融合后从同一 copy_ready 起点量到融合完成，包含排队与依赖等待。 HBM 暂缓融合时仍以全部物化分支完成为终点。 该时间不包含后续 cache refill，也不作为 T_step 的额外可加项。 存在跨层重叠时，逐层上界之和仅作宽松上界，避免重复归因。

正式对照表包含 baseline / 一对一替换 / 合并后的同字段结果。 baseline 采用匹配环境的短采样，不额外安排一轮完整功能回归。 默认保持 trace 关闭；设备计时按需采少量 step，缺测填 null。 需分源归因时，用可选分开调用的诊断模式，明确其调度与正式融合不同。 不能按字节比例分摊时间，也不能让诊断运行证明正式融合的时间分解。

21 / 22 之后使用同机器、同缓存容量、单请求的此项上界口径。 HiSparse 对照也按相同物化边界统计，不能把本方上界与对方精确等待混比。 若补充实际暴露等待作为结论，双方都使用同定义和同关联证据。 21 归档首次对照，22 复用；缺缓存容量档位时才补采样。
