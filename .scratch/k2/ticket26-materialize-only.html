A

结论与范围

交接 hybrid 与当前版都用全局行号、基址区间和 mask 完成多来源物化。 两份插件 host.cpp、kernel.cpp 逐字相同。 上层任务组织、地址表和复制路径不同。 静态差异不能直接解释性能退化。

本轮只保留 P DRAM、D DRAM、HBM cache、HBM current 到 selected KV 的一次 multibase。 其余生产代码恢复 aa5852624e15df139df7c76bb8d757341b049713。 当前广泛替换版分析基点为 93a1d9a7c9。 硬件由用户运行，baseline 不再重跑。

来源与优先级

交接文件来自 unidex-kv-handoff-20261105.zip 内： binary-v1/tests/manual/unidex_copy/native-vs-hybrid-20261105/graph-runtime/。

hybrid.manager.py:738–788 先算 cache hit，再算互斥 host miss。 没有独立 current-token 来源，当前 token 沿普通 hit/miss 路径读取。 hybrid.ops.py:171–230 把两个源放进连续全局行号区间。 Host 地址必须是已注册的 NPU 可见地址。

当前 runtime.py:784–815 中，cache hit 先排除 miss。 最新 token 仅在 miss 时从本 rank 的 current HBM 读取。 current 从剩余 miss 中剔除；其余由 prompt 长度划分 P/D。 所以逻辑优先级是 cache hit、current miss、普通 P/D miss。 并非无条件用 current 覆盖已有 cache hit。

当前 copy.py:93–118 建立 12 源槽：P、D、8 个 prefix、cache、current。 copy.py:183–218 读取 PageLocations，支持正副本选择与失效回退。 四来源物化无需这些未来来源槽。 保留 baseline 的 MempoolKVView.map_rows 即可解析分散物理页。

D

Stream 与存储

交接 hybrid.manager.py:795–858： 主 stream 生成索引并记录 copy_ready。 独立物化 stream 等待它，执行 multibase，记录 materialize_done。 attention 与原生 refill 等物化完成；slot-map 等 copy_ready 后并行执行。 attention 最终沿原路径等待 refill/slot-map。

广泛替换版稀疏 manager.py:1054–1244： 融合执行在原 miss stream，hit stream 仅记录兼容事件。 attention/refill 仍等 hit_done 与 miss_done。 slot-map 可与物化并行，结束前按原依赖汇合。

合并后 HBM hit 不再独立于 DRAM miss stream 执行。 这是物化合并本身的调度变化，不能当作保留并行度不变。

交接物化 block_dim=48；原生 refill=24、slot-map=48。 当前物化同为48，BF16 576列每行1152字节。 kernel 以 ceil(N/block_dim) 分配连续任务槽。 每核解析区间，使用两槽 FIFO 搬运行；插件保持不改。

交接每次 torch.zeros 分配 selected；显式记录 raw-pointer 数据的 stream。 广泛替换版按 batch shape 复用 selected arena。

本轮恢复 baseline 分配方式；保留 capture copier 对输出及地址表的引用。 新增跨流消费者只为融合输入记录 record_stream。 refill/slot-map 额外观察索引和生命周期补丁随观察扩展撤销。
