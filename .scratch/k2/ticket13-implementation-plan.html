C

最小数据合同

拟新增配置 observe=false、observe_sample_every=1。 采样配置只影响页集合/设备细项，不抽样生命周期与步数。 run manifest 记录配置、代码/SDK/kernel/torch_npu/CANN 版本和采样范围。 路径由验收 launcher 设置，沿用现有证据根目录。

每个进程独立写文件，例如 observe/decode-rank03.jsonl。 Main 单独一个文件；不把逐页 JSON 混进多进程 stdout。 每条记录包含 schema_version, run_id, event, host, pid, role, rank, clock_domain。 关联键使用已有 rid, room, op_id，并增加 tick_id, batch_id, forward_id, layer_id。 这些是观测键，不增加 ticket15 的控制 epoch 或新的状态机。

记录 必需内容
run 页大小、实际缓存容量、top-k、策略名、模型几何、capture/replay、拓扑与样本数
step 请求列表、tick 入口、forward 提交/完成观察、token 结果完成、执行方式
layer_pages 每页有效选择、hit、cache miss、IO miss、current_device_supply 与按源字节
selection_share producer_layer、有效 token 序列逐元素相等结果、有效长度
op kind、shard、源/目标区域、物理拷贝块与字节、各事件时间、完成证据类型
request_end prefill/decode forward 数、prebuilt 数、输出 token 数、丢弃输出的 forward、停止原因与末位置
evidence 保留的 prefix 内容比较与功能计数；由原验收器消费

页记录带 machine, attn_group, reader_numa, sharing_group。 当前 attention group 是 TP16 的组0；八个 NUMA sharing group 另记。 两种组不能混用。NUMA 字段来自配置/注册，不宣称物理驻留已验证。

页身份分两层：

  • 内容：prompt 使用 Main 已有的链式 page hash；生成段使用请求与逻辑页身份。
  • 位置：保留 source_host、region、owner/replica、physical_page 和 logical_page。

fork 仅比较共同且不可变的 prompt 内容页。 不同请求的逻辑 page0 不自动视为同一内容，复用物理槽也不沿用旧内容身份。 K1 整槽地址按现有 layout 推导；18 再替换地址解析，日志含义保持不变。

同一页可部分 hit，也可包含多个源。 记录 selected_count, hit_count, miss_count, io_miss_count，按源展开 IO 字节。 hit 标签表示所选 token 全命中；miss 标签表示至少一个 token 缺失。 保留 has_hit 表达部分命中。

selected_count = hit_count + miss_count
miss_count = io_miss_count + current_device_supply_count
token_cache_miss_rate = Σ miss_count / Σ selected_count
io_miss_rate = Σ io_miss_count / Σ selected_count
page_miss_rate = 有 cache miss 的选中页数 / 选中页数

第二条等式限当前供给路径；日后新增供给方式必须增加对应计数。 padding、无效 top-k、图补齐行和通信 padding 不进入有效读字节。 页集合去重，token 计数遵循实际选择；物理字节按真实传输计划计算。 不把一个 miss token 算成整页读取。

producer 比较有效 token 序列和 mask，不能只比页号。 记录名明确为 ordered_selection_equal；false 不自动解释为无序集合不同。 共享层保留自身 hit/miss，只有 indexer 计算归 producer。

离线入口拟为 analyze_k2_observation.py，提供四个可独立运行的子命令：

子命令 输出与分组
miss-rate 逐层按 hot_cache_tokens/策略比较；接受用户三档日志，不拿本地日志模拟不同 B
concentration 按内容页累计 IO miss 行数/字节，输出前 x% 页占比，两种单位分开
cross-step 同请求同层，交集页数 / 当前步页数；只比较真实相邻步，不把采样间隔当一步
fork-overlap 串行兄弟请求、共同 prefix、相同 decode 步与层，计算页集合 Jaccard

另提供 summarize，一次调用四项并核账在线计数。 先出 JSON/CSV 与 Markdown 汇总表，不加绘图依赖或交互仪表盘。 空分母输出 null；不完整窗口标出覆盖范围。 真实三档日志未到时，该验收项保持 pending，CPU fixture 只验证算法。

D

图内采集与时间分解

先验证图重放的计时依据，再铺开逐层打点。 首选复用现有 torch_npu.profiler 的 CPU/NPU 时间线和图任务关联。 范围包括实际 replay 的算子、拷贝、HCCL 与 stream wait。 模块级标记用于建立 layer/task 对应，不将 Python hook 用时作为设备用时。

普通 NPU Event 不能直接套 CUDA 的 external=True 用法。 官方当前源码中 Event 与 ExternalEvent 的能力不同；ExternalEvent 未启用计时。 elapsed_time/recorded_time 的实现会调用同步，因此不逐层读取。

参考 Python Event 定义与 NPUEvent 实现。 这些是 2026-11-03 查询的上游接口事实，不能证明部署版本的能力。

第一步交付一个无模型 Graph 检查入口，由用户运行。 同一张图以两组输入 replay，验证以下事实：

  1. 稳定观测 Tensor 随 replay 更新，且两步的记录不会互相覆盖。
  2. 主流、miss 流与 wait 的设备时间可定位到不同 replay。
  3. capture 建立的语义标记能可靠对应 replay task；重复 kernel 名不会串层。
  4. 实际 overlap 下可按 forward_id 取回独立记录，包含无有效行。

然后在首轮真实模型预热中核对 indexer、attention、MoE 与 HCCL 的映射。 若任务关联无法成立，该计时方案未通过；先修正具体采集接线。 不静默改成 eager，不用 host 提交时间填设备字段，不同时维护多套自动 fallback。 页计数、控制日志和离线脚本的 CPU 实施可继续；完整观测验收仍等待此关口。

图内页采集使用固定 Tensor，按 [layer, graph_batch_width, max_logical_pages] 存页内计数。 只为开启模式分配；按实际图宽分配，避免与 request slot 数混淆。

在 slot lookup 后取得 hit/cache-miss mask。 在 supply_current 后取得真正 IO miss mask及 P/D 源。 通过设备 scatter/reduction 写入页计数和 producer 相等标记。 不逐层 .cpu()、.item()、.tolist()。

快照复用现有 _Completion 生命周期。 必要时沿用其图外 clone 或 pinned copy；不能仅保存会被下一次 replay 改写的 Tensor 引用。 复用图对象/缓冲前，保证旧快照已独立保存。

不为观测新加数据路径 barrier，也不关闭现有 overlap 调度。 写文件在线批量化，压缩离线做；验收 runner 在结束正常阶段前收集已写文件。 进程退出仍由父进程处理，不能依赖逐 rank 退出回执保证日志完整。

时间表分总量、关键路径、设备忙碌三层。

量 口径
T_step D 本次推进真实 decode 的 tick 入口，到该步输出处理完成
token_ready 明确采用 scheduler 处理完采样结果、输出 token 可交付的服务内观察点
T_gap 上一步 token_ready 到本次 tick 入口的有符号差
TBT 相邻 token_ready 差；非流式 HTTP 返回间隔不能替代
T_tail Main 收到 finished 到最后一个 free_ack，均为 Main 本地时钟
T_free_P / D Main 发该侧 free 到对应 free_ack，均为 Main 本地时钟

若 overlap 使本步在上一步输出处理前开始，T_gap 可为负。 保留 schedule_gap=max(0,T_gap) 与 step_overlap=max(0,-T_gap)。 TBT=T_step+T_gap 仅用于连续且已正确关联的输出步。 单请求不意味着没有调度 overlap；不把负数裁成零后仍宣称等式成立。 首个 decode、P 首 token 和 D prebuilt 分别记录。

可相加的表只使用选定关键 rank 上的互斥区间：

T_step = indexer + cache_manage + miss_exposed + control_wait
       + collective_exposed + attention + moe + write_exposed
       + other + observer_exposed + residual

侧流 IO 的 busy 时间另列，不再整段加进 miss_exposed。 暴露 IO 是消费依赖时尚未完成的部分；按依赖边归属，不按字节比例拆时间。 未来一次多源调用无法拆时记 mixed，但源字节仍分别计数。

集合通信包含传输和等待；没有进一步证据时名称不用“纯等待”。 attention/MoE 的嵌套区间减去已独立归属的通信、读写和观测段。 并行分支取决定 join 的分支；无任务关联证据的时间进入 residual。 不能分别取各分类的跨 rank 最大值再相加。

每张表写 clock_domain、计量来源和覆盖率。 CPU 与设备时间的对齐只用 profiler 提供的关联；未经校准不直接相减。 分解失败、缺层或缺 rank 时，报告 incomplete，不能靠 residual 吞掉关键类别后报通过。

开销报告同时包含采集/传输/落盘成本和同用例开关差值，说明重叠部分。 不承诺数学上的零开销；关闭时无新增设备采集、buffer、profiler、日志或序列化。 必要的 Python 开关判断单独注明，通过同配置对照检查其实际影响。

E

操作、首 token 与三项遗留

统一按因果链记录，不用一个时间戳兼任不同阶段。

接入位置 记录什么
Main submit/_command/_receive request、route、reserve、命令发送、ack接收
Main _publish_prefix/_free_after_save publish、free发送及对应额度归还
SR execute/advance 各分片开始/完成被 tick 看到、最后分片到齐、ack发送
PoolCopyExecutor.submit/_run/poll executor_enqueue、executor_start、poll_observed；不反复记录每次空 poll
BMTransfer.transfer batch提交进入/返回、同执行线程 wait返回，作为 library_complete
PrefixStore admit/_read/release_source op1/admit、op2/load_back、op3/fill 的清单、字节、源实际释放
runtime write_layer/fetch_selected_kv write_through 和两源读；用设备时间线，保留完成观察时间

为区分 C 的排队、库执行与回执延迟，BMTransfer 内必须覆盖实际 SDK 调用。 简单的条件 observer 接口即可；不重建执行器、线程池或控制回执格式。

零块分片记录 zero_work；没有调用库时 library_complete 为 null。 op2 是设备复制，不虚构 BM 库完成；用 device_complete/observed_complete 区分。 当前版本没有远端写和 replica 读；字段登记 not_applicable，不生成假操作。

字节取 CopyBlock、现有 receipt 和实际选择 mask。 逻辑字节、物理副本总字节、通信 padding 分列。 B 用例的完整回归目标：

路径 主 KV Index K
load_back 368,050,176 B 22,020,096 B
fill 2,944,401,408 B 22,020,096 B

满32页时 admit 为64个物理页块，fill为288个物理页块。 批量合并后的调用条数另计，不能替代物理页块数。

TTFT 推荐口径：Main 感知首 token 就绪。 本轮已发起可选澄清；截至本稿未收到回复，提案采用推荐口径。 这不记为用户已确认；切换后若有新回复，以新回复更新此处。

D 的 prebuilt/首输出就绪时，rank0 发一条只用于观测的消息。 复用 SR→Main 通道，在 Main 记接收时间，不改变原生 token 输出方式。 该消息不参与 ready、publish、释放与额度判断；关闭模式不发送。

TTFT_main_observed = Main 收到首 token 就绪消息 − Main 收到请求。 报告明确包含消息传递和处理延迟，另保存 D 本地就绪时间。 P 首 token 产生、D 三条件齐和 D 首步开始也各自保留。 不跨机相减 monotonic，不把非流式 HTTP 请求总时长叫 TTFT。 若用户选择实际就绪时间估计，需要另定时钟校准与误差口径后修改这一段。

三项遗留对应输出：

  1. A/E：P send 完成观察、D handoff 到达观察、D 三条件齐、D 第一步 tick/forward。 同主机局部区间分别比较，跨机只连因果；历史 5.2s 不当作必然复现值。
  2. C fill：按16分片列 enqueue→start、SDK提交→wait返回、完成→poll、ack发送→Main接收。 最后两端跨机部分仅记各自时刻；不伪造精确网络耗时。
  3. 128/127：分别统计提交、完成、被消费输出的 forward。 记录 prefill首token、prebuilt、停止原因、额外在途但丢弃输出的 forward。

P send 的第一处可复用 defer_release(handoff=True)，D 到达可复用 transfer_complete。 这些是 scheduler 观察点；若定位要求实际 transport 完成，才扩展 Ascend conn.py 的 poll 接口。 不把 poll 时间标成 DMA 精确完成时间。 发现 bug 另开票；未复现长尾保留为未归因，并按票要求明确转交，不能编造结论。
