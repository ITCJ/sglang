13：每步分解建议采用两套相连的记录

固定一个墙钟总量，再解释关键路径；各流忙碌时间另列。 这样 21 的预取、22 的合并加入后，重叠时间不会被重复相加。

量 建议固定的边界
T_step[i] D scheduler 开始推进第 i 次真实 decode（本次控制 tick 入口），到该次 forward/sample 完成、输出 token 可交付
T_gap[i] 上一步输出就绪，到本次 tick 入口；单列排队/调度间隙，防止并发时把等待藏掉
TBT[i] 相邻输出就绪时间差，等于 T_gap[i] + T_step[i]；非流式测服务内 token 就绪，不拿 HTTP 返回间隔充数
TTFT Main 收到请求，到首个 token 满足交付条件；prefill 产出的首 token 单列
T_tail Main 收到 finished，到最后一个 free_ack；沿用 K1
T_free_P / T_free_D Main 发出该侧 free，到收到对应 free_ack；沿用 K1

K1 旧 T_step 只写“decode 开始→结束”。本次明确 tick 与 token 就绪边界， 旧约 163 ms 不直接当新口径基线。第 1 个 decode step 单列。 分别记录 n_prefill_forward / n_decode_forward / n_output_tokens、停止原因、最后位置。

输出 128 个 token 不强制等于 128 次 decode；以实际事件解决旧 128/127 问题。

可相加的主表使用关键路径上的互斥区间：

字段 归属
indexer producer 的 indexer 计算；共享层记录复用关系，不重复算 producer
cache_manage resolve、命中数据整理、替换/回填/slot map 中真正延长本步的段
miss_exposed 消费流到达依赖点后，仍须等 miss 数据的时间；按实际源分类
control_wait 当次 tick、控制消息和就绪门控导致的等待；不含已归入 T_gap 的时间
collective_exposed 集合通信在关键路径上的耗时，包含传输与等待；没有更细证据时不冒称纯等待
attention / moe attention 和 MoE 计算；已单列的集合通信从中扣除
write_exposed write_through 等写入依赖暴露的时间；避免把 D 每层写回归到 miss IO
other / residual norm、投影、采样、输出处理与未覆盖段分开标注；残差不静默摊平 
T_step = indexer + cache_manage + miss_exposed + control_wait
       + collective_exposed + attention + moe + write_exposed
       + other + residual

第二张表保留每个 kernel、拷贝和通信的原始起止及忙碌时间。 侧流 miss 与计算重叠的部分属于忙碌时间，不再加进 miss_exposed。 21/22 的对齐指标使用每个真实输出 token 暴露的 miss IO。 同一批有多个请求时，共享批次耗时只记一次，记录请求列表；不把它重复求和。

多 rank 保留原始记录，以完整关键 rank 时间线解释总量，不能相加各分类的跨 rank 最大值。

源类别为 P_remote / D_local / replica，同时保留实际 region、机器与 NUMA。 单次多基址调用若无法拆出各源耗时，时间记 mixed；按源字节仍精确计。 不按字节比例虚构每个源的耗时。

实现只在观测模式开启时装配图内计数/时间点，复用实际依赖事件。 图 replay 不执行 Python 层 hook，不能用 Python 提交时长当逐层设备时间。 先验证计时点能随图重复更新；图内观测缓冲稳定，图外在已有完成点后收集。

不为计时逐层 synchronize，不在网络线程新增集合通信。 主机用 monotonic 时间，设备用设备时间线；保留 clock_domain。 P/D 单调时钟不直接相减，跨机用消息关联和各端局部区间解释。

TTFT 记录 route、reserve、load_back、prefill/chunk、handoff 和三条件到齐。 这些区间可能重叠；同样按关键路径核账，不把各段 wall time 硬加。 每 op 保留 submit、library_complete、ack、publish、source_release、credit_return。

不适用的事件留空并说明，不能拿 ack 时间补造库完成时间。

13：页集合与离线分析的数据合同

单个页可能只有一部分选中 token 命中，必须保留页内计数。 只有“这页命中/缺失”一个布尔值，不能重算 token 缺失率。

层次 JSON lines 的必要信息
标识 schema_version、run、request、step、layer、rank、machine、attn_group、reader_numa、batch_id
配置 page_size_tokens、hot_cache_tokens、top_k、replacement_policy、采样范围/轮次
每页 logical_page、稳定内容标识或 prefix hash、region/physical_page、selected_count、hit_count、miss_count、io_miss_count、miss_source 及分源字节
页面标签 hit 表示本页所选行全部命中；miss 表示至少一行缺失，附 has_hit 及上述计数表达部分命中
选择复用 producer_layer、与 producer 的有效 token 选择是否相同；不能仅比页集合就声称 token 选择相同
当前 token 单列 current_device_supply；它可属于缓存 miss，但不产生主存 miss IO

页号需带源/内容身份；不同请求的逻辑 page 0 不是同一物理页。 fork Jaccard 在共同 prefix 的内容页身份上比较，避免把不同内容误算重合。 票 19 的温度键采用不可变内容页与读者 NUMA，描述符保留机器/区域定位。

padding、无效 top-k 和补齐通信不计有效 token 或读字节。 页集合去重；token 缺失率按真实有效选择计数，物理搬运字节另外按实际传输计数。 同一页发生多源读取时按源展开，不强行只填一个来源。

token_cache_miss_rate = sum(miss_count) / sum(hit_count + miss_count)
io_miss_rate = sum(io_miss_count) / sum(selected_count)
page_miss_rate  = count(至少一行 miss 的选中页) / count(选中页)
cross_step_overlap = |pages[i] ∩ pages[i-1]| / |pages[i]|
fork_jaccard = |pages[a] ∩ pages[b]| / |pages[a] ∪ pages[b]|

miss_count 取热缓存查询结果；io_miss_count 取实际主存读取计划。 当前 token 的本地直供属于前者、从后者扣除，不能用 IO 缺失率冒充缓存缺失率。

当前 token 的本地直供另报占比；空分母输出 null 并写明无样本。 集中度与票19温度按页累计实际 IO miss 行数/字节，两种曲线标明单位。 用户 k/2k/4k 日志直接使用同一字段合同；不只从页级布尔值推 token 缺失率。

page_size_tokens=128；hot_cache_tokens=2048/4096/8192，明确区分两种 B。

模式默认关；关闭时不建观测 buffer/event、不收集页集合、不写日志。 开启时记录自身 CPU/设备收集开销及同用例开关差异，最多两轮、首轮预热、注明 n。 既有 K1 删除项引用原清单；本票只登记实际残留的删除或迁入项。

依据：miss 路径与事件、 attention 消费等待、 当前 token 直供、 K1 清理记录。

25：首版建议采用库完成

选 BM 库实际执行远端写，再用库完成确认。 P 侧目前 eager，可以复用独立执行器；D 的图仍只消费已就绪的页。 SDK v1.1.4 的 L2G 批量方向走设备→全局主机拷贝， wait 取调用线程对应的内部 stream。因此提交和 wait 必须在同一个执行器线程。

P prefix 候选页的本机写也要完成，才能报告对应的可发布状态。 只累计已完成且连续的 token 范围；D 仍等 prompt、Index K、handoff 三条件。 失败、超时或完成未知沿现有 fail-stop，不提前复用源 HBM 或目标页。

批量子提交错误传播沿票 11 的已交付 SDK 补丁核对，不自动升级外部 SDK。

BM wait 不覆盖 UNIDEX 直接写远端地址的操作。 普通 torch Event 也没有在本项目中证明对端读者可见这一语义。 若后续改成 UNIDEX 直写，需要独立确认远端完成 fence/顺序协议， 并用真实 D 设备消费验证；当前未找到可直接复用的该类 fence 封装。

不能在 UNIDEX 后补一个空 BM wait 就宣布完成。

这项建议把 25 的远端写执行路径具体化为库 L2G， 不是对原 UNIDEX store 补调用。14 必须测同一路径； 是否达到层间隐藏条件、对端立即可读、错误传播均留待真实硬件结果。 不增加 P alive 中转，也不引入 D→P 整段回拷。

接口事实参考 MemFabric 官方 Python API。 本次另核对本地 SDK 的 v1.1.4（c01f3ad842b9）： smem_bm.h 的 copy_batch/wait 声明， hybm_data_op_sdma.cpp 的 BatchDataCopy、Wait、InnerWait。 它们支持接口与 stream 选择判断，不代替部署二进制的远端可见性验证。
