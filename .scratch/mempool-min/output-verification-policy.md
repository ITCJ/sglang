## 后续逻辑题与长度合同

ticket04实现新测试入口前，现有脚本仍按旧严格输出规则执行。不得仅把旧错误忽略后
标记新验收成功。新报告须标识本约定，并分别保存结构检查、答案、完整IDs比较与覆盖范围。

1. 使用可读自然语言、事实表或简单操作序列。标准答案由独立fixture或CPU规则生成，
   不让另一个语言模型判断，也不把目标答案泄漏进该请求的题面。
2. 至少覆盖前缀中的信息检索、简单加减/条件判断，以及新增后缀改变最终答案。
   用题面中前部、中部和尾部的事实建立依赖，避免只有最后一句参与答案。
   可以在同一ABCE组内包含多个短字段，避免无必要地反复加载模型。
3. 使用实际模型tokenizer和有效模板生成固定输入：A/C/E=4096，B=5120。
   必须直接断言 C_ids==A_ids、B_ids[:4096]==A_ids；不能只比较文本长度。
   E 使用不同的首个token页，实际命中必须为0。补足长度使用确定、可读的材料，
   不随机拼词表ID，也不能截断问题、关键事实或模板以凑长度。
4. B 的1024-token新增后缀必须影响至少一个标准答案字段，检出遗漏后缀或沿用A答案。
   C 的题目与A相同。E提供另一组事实，检出槽位复用后读到旧请求内容。
5. 参考与目标使用完全相同的已保存input IDs、模型、采样配置和部署条件。
   每组从独立且空的目标prefix开始，A实际命中0；参考不污染目标目录。
   保留0/4096/3968/0命中与32/40/40/40页占用的严格断言。
6. 逻辑题保持thinking关闭、greedy、生成上限128，答案采用短而确定的字段格式。
   允许自然EOS；不得把实际短生成记为128步负载覆盖。提前EOS、完整生成负载和
   资源尾页清理按各自用例报告，长生成控制也使用有意义的输入。

## 失败判定

| 检查 | 判定 |
|---|---|
| KV复制、恢复与fill的逻辑内容 | 全部必要rank/层按实际映射精确核对；任何差异失败，不设浮点容差 |
| ready、ack、源保护、handoff、free_ack、资源账本 | 必须符合因果和所有权合同；缺证据、提前就绪/释放或错误绑定失败 |
| 逻辑答案 | 参考和目标分别与独立标准答案比较全部字段；错误、缺字段、格式无法解析或截断均不通过 |
| 冷算正确、复用错误 | 功能验证失败，恢复实现排查；不能套用已知归约差异豁免 |
| 冷算参考本身错误 | 标记基线/题目有效性失败，不能证明复用有错，也不能记该题通过；保留双方输出 |
| 完整output IDs | 每次保存并比较完整序列，报告长度、是否相等与首差；跨形状不相等不再单独判定缓存实现失败 |
| 同条件重复 | 保留稳定性诊断；新出现的不稳定或与已知范围不同的异常单独报告和分析 |
| 未执行的覆盖 | 明确标记not-run，不由CPU、语义smoke或其他票的结果代替 |

“语义正确”指可自动验证的标准答案正确，不是文字看起来合理、回答相似或只比首token。
这些测试与精确KV/生命周期检查联合验收，不把模型答题表现当作缓存正确性的唯一证据。
不设置未经校准的ULP、logit或KL通用阈值，也不声称生成token跨所有形状逐位不变。

## 版本与证据

记录代码版本和工作区差异、模型/tokenizer/量化身份、启动与采样参数、真实命中、
prefix占用、完整input/output IDs、标准答案、解析结果、rid/rank/op_id与设备完成证据。
改变计算实现或模型配置后重新生成对应冷算参考和缓存来源；不得静默复用旧条件下的KV。
硬件由用户运行；入口继续每机一条命令，自动就绪、请求、校验、收集和清理自身进程。
