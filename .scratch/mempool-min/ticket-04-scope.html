正常用例怎样运行

参考组关闭 match_prefix，为相同输入生成冷算结果。 目标组使用独立目录和池，从空 prefix 开始执行下表。

请求 prompt token 命中 token P 新算 token 结束时 prefix 页／份 要证明的行为
A：冷请求 4096 0 4096 32 正确计算并保存 prefix
B：A 加后缀 5120 4096 1024 40 复用 A，并计算会改变答案的后缀
C：再次请求 A 4096 3968 128 40 恢复 31 页，重算最后一页，不重复保存
E：不同内容 4096 0 4096 40 满 prefix 跳过保存，并复用已归还的槽

统一 page_size=128，每份 prefix 共 40 页。 C 为首 token 的计算保留最后一页，因此命中 3968。 E 的首个 token 页必须不同，答案也依赖新事实。 E 必须取得此前真实 free_ack 后的最小空闲 P／D 槽。

固定环境为 GLM-5.2，P／D 各 TP16，P eager、D NPU Graph。 请求串行、单 chunk、各 rank 私有副本，生成上限为 128。 S_P=8192、S_D=128，每侧每 rank 16 个槽。 实际容量须覆盖 5120-token prompt 和 128-token 生成上限。
