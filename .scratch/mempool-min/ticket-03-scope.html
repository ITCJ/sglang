命中上限为 floor((prompt_len - 1) / page_size) × page_size。 C 恢复 31 个完整页，最后 128 token 在第 32 页计算并采样首 token。 旧记录中的 4032 和半页接续已被统一页设计替代。

C

为什么命中后要复制两次

操作 复制到哪里 用途
load_back（op2） prefix → P 原生 HBM P 用命中段计算后缀
fill（op1） prefix → 新请求 P alive D 经该请求绑定读取命中段
admit（op3） P alive → prefix 结束后保存缺失页，沿用 02 基础

load_back 和 fill 都包含主 KV 与 Index K。 主 KV 有 78 层，compact 576 维；恢复 HBM 时拆回 512／64 两部分。 Index K 有 21 个 producer 层、128 维，须另行恢复。

原生 allocator 返回真实 token 索引，可能不连续。 prefix_indices 必须有 hit_len 个逐 token 索引。 C 对应 3968 个索引，且不包含尚未计算的最后 128 token。

命中请求仍获得独立 P／D alive，分别扣除 64／1 页整槽额度。 按生成上限 128，B／C 的 D Index K 分别预留 41／33 页。 P 原生 HBM 仍须容纳完整 prompt，包括恢复段和新算段。

D

最容易写错的是完成条件

load_back 完成后，fill 与后缀计算可以独立推进。 fill 写 [0, hit_len)，后缀写 [hit_len, prompt_len)。 是否在设备上实际重叠，必须由 NPU 测量确认。

以请求 B 为例，下面的“完成”包含全部必要 rank 的主 KV 和 Index K。

fill 命中段 后缀写回 alive 的连续 ready_tokens D 能否开始
未完成 已完成 1024 token 0 继续等待
已完成 4096 token 未完成 4096 继续等待
已完成 已完成 5120 还须等完整 Index K 与 handoff

后缀使用独立范围跟踪器，内部计数从零开始。 不能把旧写回计数器预填成 hit_len，冒充命中段已经写入 alive。

P 发送由恢复段和新算段组成的完整 Index K，并交接首 token 与 metadata。 D 必须同时等到 Router ready、全部必要 rank 的 Index K 和 handoff。

P 后缀写回与原生发送完成后，可释放原生 HBM／请求行。 该释放不等待 fill，因为 fill 直接读取 prefix。 alive 整槽仍须等最后复制依赖及显式 free_ack，才能归还额度。

Main 在计划 load_back 和 fill 时，分别保护 prefix 来源。 每个操作只有收到真实完成 ack，才按自己的 op_id 解锁一次。 迟到 rank 不得造成提前 ready；重复 ack 不得重复解锁。 恢复、复制或推理失败时沿用 fail-stop，并停止新操作与 free。
