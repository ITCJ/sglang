存储区域与容量

保留 P／D 私有副本、layer-first、统一 B=128 和 alive 整槽分配。 prefix 真正按页分配；主 KV 与 Index K 共用一组 prefix 页号。 每份逻辑容量为 40 页，各 rank 的 16 份副本不叠加为 640 页内容。

P 每 rank 区域 几何 Payload
现有 alive 主 KV 78 层 × 16 槽 × 8192 token × 1152 B 11232 MiB
新增 alive Index K 21 层 × 16 槽 × 8192 token × 256 B 672 MiB
新增 prefix 主 KV 78 层 × 40 页 × 128 token × 1152 B 438.75 MiB
新增 prefix Index K 21 层 × 40 页 × 128 token × 256 B 26.25 MiB

P payload 合计 12369 MiB，probe 位于全部区域之后。 按现有 1 GiB 分配对齐，P 从 11 GiB/rank 增为 13 GiB/rank。 TP16 的 P BM 贡献为 208 GiB，D 仍为 16 GiB。 这些是 BM 分配量，不包含模型、进程和验收参考缓冲。

P/D 启动使用相同 PoolLayout 签名，包含 P 的新增区域。 D 只贡献自己的生成主 KV 区域；不新增 D Index K DRAM 写回。 注册分别报告全局布局和本侧实际区域，校验 TP16、容量与四类副本。

runner 从同一布局计算容量，替换现有硬编码的 P 176 GiB 检查。 实际 NUMA 页落点仍须单独取得硬件证据。

复制复用现有 UniDexCopy 的双 raw-pointer 模式。 本地算子实现 支持独立的 src_ptr／dst_ptr，并在当前 NPU stream 提交。

worker 使用已验证的设备地址；Main 只处理不透明描述符。 不通过 CPU 指针解引用 BM 设备映射。 实际双指针复制内容与完成可见性由本票 NPU 验收验证。

C

先让 Index K 成为可靠的保存源

runtime 初始化时取得原生 NPU KV pool，并校验实际 producer 层列表。 当前模型为 (0, 1, 2, 6, 10, ..., 74)，共 21 层，128 维 BF16、无 scale。 write_layer 只对 producer 层新增 Index K 写回。

从原生池按真实 out_cache_loc gather，支持非连续物理行。 沿用已有 row／slot／position 有效掩码，新增独立 Index K 计数。 事件覆盖主 KV 与 Index K 的所有提交，并保留临时张量到设备完成。 漏 producer、少写或无效位置不能发布完整 prompt ready。 writes_done 和 detach_row 同时受两类写入完成约束。 service 因而继续按既有条件释放 HBM／请求行。

fake warmup 的预期写入为空，Graph padding 没有真实绑定。 新增 Index K 路径必须跳过这些行，不读取无效物理地址。 P native 释放之后，admit 只从 alive DRAM 读取。 复制身份与完成收据按 rid／attempt／op_id 保留，独立于已归还请求行。

D

admit、publish 与 free 怎样接起来

Main 保留现有页哈希与命名空间种子。 目录中同一哈希分别保存 alive 位置和 retained prefix 位置。 位置分别记录状态、owner hold 和操作锁；新冷请求不能覆盖已有 ready prefix。 父关系和 child_count 只随真实目录增删更新，重复冷算不重复增加。 本票继续固定 hit_len=0。

Main 的必要变化

  • finished 与 P native_freed 分别留证，两种到达顺序都可推进。
  • finished 时归还已实际释放的 D 原生额度；alive 等独立 free_ack。
  • 跳过 ready prefix，容量不足时保留连续可发布范围，从尾部缩短。
  • 对待复制源先加锁，再撤 owner hold：源引用为 1 → 2 → 1 → 0。
  • 保护所需父路径；ack 后按父页先于子页的顺序发布。
  • 校验源绑定、目标页号、区域、rank、层覆盖和设备完成身份。
  • 相同 ack 幂等，冲突 ack fail-stop；每个 op_id 只解锁一次。
  • _complete 只要求请求资源归还，允许 prefix 继续占用页额度。
  • 保留 ready prefix 目录，清除本请求 alive 位置及无用节点。

没有待保存页时直接进入既有显式释放路径。 首版让两侧 alive 都在 admit 完成后 free，保持串行结束路径简单。 请求结果返回及下一请求还须等待两侧 free_ack 与后端输出。 Main trace 先记录收到的事件，再记录由它触发的命令，支持因果核对。

SR 与 prefix store 的必要变化

prefix.py 集中管理页占用、操作状态、复制事件和目标可读收据。 拟定小接口包括空闲页快照、幂等 admit/poll 和源释放检查。 操作记录使用有名字段：请求身份、槽、源页、目标页、event、临时张量与收据。 请求实际 free 后清理操作记录；已保存 prefix 页继续保留。

每次 scheduler tick 仍使用现有两次 TP gather。 第一次汇总包括空闲 prefix 页，协调者据此统一目标页号。 各分片验证并占用同一页集合，随后各自提交本地复制。

设备未完成返回 pending；已完成分片缓存收据，下一 tick 不重复复制。 第二次 gather 只有收齐全部 rank 才共同移除队首命令并确认 op_id。 rank 0 在此之后发送 admit_ack，避免快慢 rank 的 pending 队列分叉。

free 在本地再次检查源没有未完成复制，然后调用现有 control.router_free。 错误或超时保留 writing 目标和受保护源，沿用现有 fail-stop。 本票不提供失败重试、evict、load_back 或 fill；后两项属于 ticket03。

内容验证链

验收模式逐层保存实际计算值的 CPU 参考，避免在 NPU 累积整段克隆。 主 KV 按 compact 576 维规范化；Index K 按 producer 层和逻辑 token 排列。 在以下三个时点逐逻辑 token 比较值，并记录 rank／层／页号：

  1. 写回完成后，比较原始计算值与 alive 内容。
  2. P native 释放且 admit 完成后，比较 prefix 内容。
  3. alive 实际 free 后，再次读取并比较保留内容。

验收参考只保留当前请求及已发布的 40 页，过期内容及时释放。 逐值比较结果之外可记录逐页摘要，关联后续 C/E 的内容不变性。 报告判定放在验收脚本，运行时只在显式验收模式采集所需内容与证据。 该模式的额外读回和同步不用于性能结论，容量检查单列验证缓冲。
