## 运行范围

- Ascend NPU 双机 GLM-5.2，P／D 各 TP16、attention DP1、PP1、普通非投机 decode；
  主 KV 为 78 个独立层、compact 576 维 BF16，Index K 为 21 个 producer 层、
  128 维 BF16，无独立 scale。
- 串行、单 chunk、各 rank 私有副本、足额 reserve、fail-stop；输入为 token IDs、
  greedy，原生 radix cache 关闭。D 生成段 Index K 保留 HBM，sparse decode admit 关闭。
- S_P = 8192、S_D = 128，每侧每 rank 16 个存储槽；DRAM 与原生 HBM 统一使用 page_size=B，
  P/D 和相关池必须严格相同；当前部署默认且仅允许 B=128；生成上限 128。
- P eager、D NPU Graph；context、单 chunk 与实际 HBM 容量必须覆盖 5120-token
  prompt、128-token 生成上限及原生必要余量，不能缩短用例替代容量验证。
- 沿用当前 NUMA 连续均分规则与实际机器拓扑；硬件容量、映射和可见性须有对应证据。
  dense baseline、sparse K1 和旧共享性能票不构成本票依赖。

prefix 位于 P 机，每 rank 一份、每份 40 个逻辑页（5120/B），主 KV 和 Index K 均按实际完成保存。

## 完整用例与预期结果

参考组关闭 match_prefix，为目标请求生成同模型、同输入、同参数的完整冷算输出。
目标组独立初始化目录和池，从空 prefix 开始严格执行 A → B → C → E。
两组可顺序启动，参考缓存不能污染目标组；旧短请求归档不作为本次参考。

按[2026-10-27输出约定](../output-verification-policy.md)构造可读逻辑题和独立标准答案。
用真实tokenizer核对A/C/E的4096、B的5120；B前4096 IDs等于A、C等于A，E首个页不同。
题目覆盖前缀信息检索、简单条件/算术和B后缀更新，不能仅靠末尾一句得出所有答案。
参考与目标分别核对短字段答案；冷算错误标记基线失败，冷算正确而复用错误仍失败。
保存完整IDs与首差，跨形状不等不单独作为缓存实现失败；复制与生命周期不得放宽。
语义题允许自然EOS、生成上限128；实际步数、长生成和提前EOS清理分别报告。

| 用例 | prompt token 数 | hit_len | P 新算 token 数 | D Index K 预留页／rank | 结束时 prefix 页／份 |
|---|---|---|---|---|---|
| A：冷请求 | 4096 | 0 | 4096 | 33 | 32 |
| B：A 加 1024 个新 token | 5120 | 4096 | 1024 | 41 | 40 |
| C：与 A 相同 | 4096 | 3968 | 128 | 33 | 40 |
| E：不同内容的冷请求 | 4096 | 0 | 4096 | 33 | 40 |

每个请求的 P alive 都扣一个整槽，即 64 页额度；D alive 扣一个整槽，即 1 页。
prefix 容量按每份的 40 个逻辑页计算，不能累加副本容量。E 必须因 prefix 已满
而跳过 admit，同时取得此前实际归还的最小空闲 P／D 槽，并保持自己的输出正确。

## 启动与自动协调

复用 01 交付、02／03 扩展的同一入口，提供常驻服务与完整验收模式。两机各执行
一条命令，配置包含地址、模型身份、网卡、NUMA、容量与日志目录，使用相同 run_id。
P 侧启动独立 Main Router 和 P 服务，D 侧启动 D 服务；SR 随各 worker 自动加载。

自动协调的完整路径为：

1. 校验两侧环境、配置摘要、代码版本与模型身份，记录实际展开的启动参数。
2. 启动 Main 和两侧服务；BM 映射先于 D Graph capture。原生握手和全部资源注册
   完成后 Main 才就绪；健康检查不使用可绕过 Router 的真实 warmup 请求。
3. 获取独立冷算参考，保存实际 input／output IDs 与采样参数，再运行目标组。
4. 顺序执行 A／B／C／E，确认真实 decode、复制内容、来源、账本和释放事件。
5. 运行四类入口拒绝用例；错误／超时注入使用独立运行，避免污染成功组。
6. 汇集两机、Main、全部必要 rank 的日志，逐项生成 V1–V10 结果与失败定位。
7. 无论成败均清理本轮启动的进程；失败返回非零，失联或强制终止不能记作 free_ack。

常驻服务只通过 Main 接收业务请求。区分进程存活、完整控制就绪和当前请求是否空闲。
阶段 0 保持私有副本和真实串行；不以修改 share 开关替代后续共享接入。

## V1–V10 证据合同

| 项目 | 本票在最终集成版本必须证明的行为 |
|---|---|
| V1 命中 | B=4096、C=3968，route 可追溯真实 prefix 来源 |
| V2 复制 | 全部必要 rank／层逐逻辑 token 核对 fill、HBM 两部分和 Index K，采用实际 token 映射 |
| V3 输出 | A/B/C/E的参考与目标分别通过独立标准答案；完整IDs相等与首差独立报告，按现行输出约定判定 |
| V4 真实来源 | D 读取正确的 P／D 槽、偏移和内容，补充 P-only／D-only／混合适配器结果 |
| V5 P 提前释放 | P native 在 D finished 前释放，之后生成仍正确；保留完成与因果依据 |
| V6 账本 | 各请求最终恢复 alive 和 D 原生资源；prefix=32→40→40→40；B 整槽等 admit 后归还 |
| V7 完整页边界接续 | C 恢复 3968 个索引（31 个完整页），最后 128 token 在第 32 页重算；不重复保存，另测提前结束的清理 |
| V8 入口拒绝 | 超 P_max、未按 B 对齐、生成上限超 128、注册容量不足均拒绝，目录和账本不变 |
| V9 释放复用 | E 的 alloc 对应此前真实 free_ack 的槽；free_ack 晚于全部对应读写与依赖完成 |
| V10 真实负载 | D 每步常驻与执行请求数均 ≤1，不能用 Graph padding 行数代替 |

真实 sparse 选择可能使某层仅从一侧取数，不要求每层两侧都有正字节传输。
不使用清零 P KV 的负向用例。完整输出继续逐token记录比较；使用独立标准答案和
严格数据链路检查验收，不以首token、文字相似或任意数值容差替代。

结构化报告关联 run_id、版本及工作区差异、模型／tokenizer／量化身份、配置、
input／output IDs、rid、op_id、rank、位置／槽号及设备完成。route／alloc／ack／
publish／finished／free_ack 和 D 每步负载必须可追溯。跨机裸时间戳不能单独证明
释放顺序；缺 rank、缺完成证据、未执行或失败项明确标记，不默认为通过。
