## B 正常用例怎样运行

参考组关闭 match_prefix，为相同输入生成冷算结果。
目标组使用独立目录和池，从空 prefix 开始执行下表。

| 请求 | prompt token | 命中 token | P 新算 token | 结束时 prefix 页／份 | 要证明的行为 |
|---|---:|---:|---:|---:|---|
| A：冷请求 | 4096 | 0 | 4096 | 32 | 正确计算并保存 prefix |
| B：A 加后缀 | 5120 | 4096 | 1024 | 40 | 复用 A，并计算会改变答案的后缀 |
| C：再次请求 A | 4096 | 3968 | 128 | 40 | 恢复 31 页，重算最后一页，不重复保存 |
| E：不同内容 | 4096 | 0 | 4096 | 40 | 满 prefix 跳过保存，并复用已归还的槽 |

统一 `page_size=128`，每份 prefix 共 40 页。
C 为首 token 的计算保留最后一页，因此命中 3968。
E 的首个 token 页必须不同，答案也依赖新事实。
E 必须取得此前真实 free_ack 后的最小空闲 P／D 槽。

固定环境为 GLM-5.2，P／D 各 TP16，P eager、D NPU Graph。
请求串行、单 chunk、各 rank 私有副本，生成上限为 128。
S_P=8192、S_D=128，每侧每 rank 16 个槽。
实际容量须覆盖 5120-token prompt 和 128-token 生成上限。

## C 新逻辑题与判定规则

用真实 tokenizer 生成固定长度的可读题目。
直接核对 `C_ids == A_ids` 与 `B_ids[:4096] == A_ids`。
题目包含前缀检索、简单算术或条件，以及 B 的后缀更新。
答案依赖题目前部、中部和尾部，使用短字段格式。

| 检查 | 判定合同 |
|---|---|
| 独立标准答案 | fixture 或 CPU 规则生成；参考组和目标组分别核对 |
| 冷算正确、复用错误 | 功能验证失败，继续排查实现 |
| 冷算本身错误 | 标记基线或题目有效性失败，保留双方输出 |
| 完整输出 IDs | 保存全部序列，报告长度、是否相同及首差 |
| 跨形状 IDs 不同 | 单独报告；不再仅凭这一项判定缓存实现失败 |
| KV 内容与生命周期 | 继续精确检查；缺证据或错误绑定均失败 |

逻辑题关闭 thinking，使用 greedy，允许自然 EOS。
提前 EOS、长生成负载和尾页清理分别报告。
实际短生成不能记作 128 步负载覆盖。
旧合成 C 的失败记录保留，新规则不追溯改写旧报告。

## D 完整验收还必须覆盖什么

| 验收项 | 最终版本需要给出的证据 |
|---|---|
| V1 命中 | B=4096、C=3968，且来源可追溯 |
| V2 复制 | 全部必要 rank／层，按实际映射精确核对逻辑内容 |
| V3 输出 | 参考与目标分别通过标准答案；完整 IDs 差异另报 |
| V4 来源 | 正确读取 P／D 槽、偏移和内容；补充三类来源适配器检查 |
| V5 P 提前释放 | P native 在 D finished 前释放，后续生成正确 |
| V6 账本 | alive 与 D 原生资源归还；prefix 为 32→40→40→40 |
| V7 页边界 | C 重算最后 128 token，不重复保存；另测提前 EOS 清理 |
| V8 拒绝 | 超长、未对齐、生成上限超 128、注册容量不足均拒绝 |
| V9 复用 | E 复用真实归还的槽；free_ack 晚于对应操作完成 |
| V10 负载 | D 每步真实常驻与执行请求数均不超过 1 |

拒绝请求后，目录和账本保持原值。
错误与超时注入使用独立运行，检查 fail-stop 和清理。
强制结束进程不能当作 free_ack。
缺 rank、缺设备完成证据、未执行或失败项均单独标记。

## E 用户会拿到怎样的入口

复用 [run_mempool_min.py](../../ascend-mempool-test/scripts/run_mempool_min.py) 的启动链。
P 侧启动独立 Main Router 和 P 服务，D 侧启动 D 服务。
SR 随 worker 加载，两机使用相同 run_id。

```flow
环境与身份核对 -> 双机启动与注册: 自动协调
双机启动与注册 -> 独立冷算参考: 就绪后提交请求
独立冷算参考 -> 目标ABCE: 使用相同input IDs
目标ABCE -> 拒绝与独立故障运行: 记录账本和完成事件
拒绝与独立故障运行 -> V1至V10报告: 汇集两机与必要rank证据
V1至V10报告 -> 清理自身进程: 无论成败都执行
```

入口继续提供常驻服务与完整验收模式。
报告保存在 `/home/cryang/log/` 下的独立运行目录。
报告关联版本、配置、模型身份、rid、op_id、rank 与槽位。
入口失败返回非零，并只清理本轮启动的进程。
实际 CLI 命令随实现交付；本页不预先定义新参数。
