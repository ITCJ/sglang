B

最小空闲 slot 0 与 page 的关系

依据：walkthrough 第 0、3、5 节，M17、M31、M40。 阶段 0 的 DRAM 逻辑页与原生 HBM 页统一为可配置的 B token，当前部署 B=128。 alive 暂时按整槽分配，页表描述其中的有效数据。

以 S_P = 8192、prompt = 4096 为例：

项 数值与含义
一个 P 存储槽 8192 / B = 64 个逻辑页额度
slot 0 对应池内逻辑页 0–63
本次有效数据 使用 slot 0 的前 32 页，即页 0–31
剩余尾部 页 32–63 仍被本请求占住，不能再次分配
释放 最后一项依赖完成后归还整槽，收到 free_ack 才恢复额度

“最小空闲槽”表示从空闲槽中选编号最小者。 全空时选 0；若 0 被占用且 1 空闲，则选 1。 这个规则用于明确验证归还后的复用。 它既不是“最小空闲页”，也不是原生 req_pool_idx。

阶段 0 alive：逻辑页接口 → 连续存储槽临时后端
阶段 0 prefix：逻辑页接口 → 真正的页分配器
阶段 1：调整为 page-first 布局
阶段 3：alive 替换成真正的页分配器，读路径支持散页

page-first 改变数据排列；页分配器改变分配和回收单位。 两项工作分别安排在阶段 1 和阶段 3。 原生 HBM 与 DRAM 注册同一个 B；只满足整数倍关系仍须拒绝。

C

两个 rank 共用 NUMA 与共用一份 KV

依据：walkthrough 第 0、3、8.3 节，M12、M20、M37。 NUMA 分配决定请求在哪个节点分配内存。 共享决定两个 rank 是否映射同一份物理数据。 只把 rank 0、rank 1 放到 NUMA 0，不会自动合并副本。

示例 阶段 0 私有副本 K1 共享目标
rank 0 和 rank 1 各持有一份完整主 KV 同属共享组，持有同一份主 KV
逻辑 page 7 页号相同，背后是两份物理内容 组内同一逻辑页对应同一份物理内容
写入 两个 rank 各完整写自己那份 按配置分工写入，汇总后供所有 reader 读取
地址 各进程解析自己的映射 共享物理内容，进程虚拟地址仍可不同
TP16、每 NUMA 两个 rank 每侧 16 份 alive 主 KV 每侧 8 份 alive 主 KV

K1 的四类副本数必须分别处理：

数据类型 阶段 0 K1
alive 主 KV，R_am 16 8；默认每组 2 个 rank
P alive Index K，R_ai 16 1
prefix 主 KV，R_pm 16 1
prefix Index K，R_pi 16 1

D 生成的 Index K 在这两个阶段仍只留在 HBM。 K1 还包括单份 prefix 的 load_back 读取与广播。 SR 分片数量由 worker 数量决定，不等于物理副本数。 共享后分片解析组映射；Router 仍只处理逻辑位置和不透明描述符。
