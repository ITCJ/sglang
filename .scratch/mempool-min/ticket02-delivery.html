正常路径、所有权与完成条件

P native 清理和 D finished 的两种到达顺序都可推进。 Main 持有逻辑目录和额度；SR/control 持有真实 alive 槽；PrefixStore 持有本 rank 的 prefix 页。 native 请求行释放后，操作通过 rid/attempt/op_id 及实际源槽继续关联。

源引用按 owner hold 1→2→1→0 变化；最后一个 rank 完成之前保留源与 writing 目标。 copy 使用 UniDexCopy 双设备指针，不在 CPU 解引用 BM 地址。

已有 prefix 在重复冷算时保留；新页只能接在可发布父路径后。 容量不足时缩短待保存尾部，满容量时跳过 admit。 错误或超时 fail-stop，保留 writing 页及受保护源；不制造 free_ack。 warmup 保持原生本机路径，不建立 alive 绑定，也不触发 prefix 写回或占用。
