B

池与会话怎样接入

每侧副本的成员列表都是 [i]，owner 是该侧 rank i。 一个跨 P/D 的 BM 会话仍包含 P_i 和 D_i 两个参与者。 “成员数 1”指每侧副本成员数，不是 BM 会话总人数。

将两参与者专用接口换成能表达多成员的接口。 接入端口、BM 初始化、池映射、Graph 访问和关闭路径。 请求结束后复用槽位；服务关闭前先排空设备访问。

现有服务入口仍调用 initialize_rank_pair()。 实验中的 SharingPool 已能区分参与者编号与 P/D 逻辑视图。 本票把该能力接到服务生命周期中。

C

ready_tokens 改为覆盖位图

协调者为每份副本记录“哪些页已实际写完”。 它从第 0 页起计算连续完成范围，再汇总必要副本与 Index K。

命中长度本身不能证明 fill 已完成。 新算段写完，也不能跳过未完成的命中段。 保留现有写入连续性检查和首 token 的三条件门控。

本票仍是单写者。 验收时，让位图与原计数器消费同一轮完成事件。 两种算法的 ready_tokens 序列必须逐事件相同。

D

free_ack 改为读者计数

协调者为每份副本记录尚未停止访问的读者数。 本票初值为 1；对应读者完成 drain 后减为 0。

计数归零是释放条件之一。 保留 native 清理、prefix 保存及 source 释放约束。 对 Main 发出 free_ack 的逻辑时点应与阶段 0 一致。

后续 05 / 06 会把对应计数扩展到两个读者。 本票先验证一个读者时的行为等价。
