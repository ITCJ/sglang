# Ticket12 第一步：拷贝接口与宽地址

2026-11-02，本机CPU与本地内核源码核对；NPU未运行。
数值结果见[cpu-contract.json](cpu-contract.json)。

核对本地`sgl-kernel-npu`的`unidex_copy.cpp`与`unidex_copy_kernel.cpp`：
host接受int64原始地址、int64行索引，但检查`rows × block_bytes <= UINT32_MAX`，
单行最多32 KiB；device把行偏移转换为uint32，基址仍为完整GM地址。
源码版本与SHA256已记入JSON，不能只凭索引dtype为int64推断宽偏移安全。

小几何oracle按slot/page/layer/token/feature枚举物理存储，验证分段行集落到独立期望值。
真实P区域为11,777,605,632 B，最后槽偏移11,041,505,280 B；每槽736,100,352 B。
用完整64位槽基址和槽内行偏移即可访问最后槽，偏移算术未超过32位。
其他四类区域及prefix实际五页段同样满足分段跨度要求。

采用现有内核。大区域固定按槽提交，设备mask按稳定绑定筛选实际有效行；
图中保留零有效调用，换槽无需主机读回或重新捕获。旧96 GiB组件池的槽可能大于4 GiB，此时按完整页进一步分段；
小于4 GiB的整个区域可一次提交，
prefix使用所在段的实际几何。物理行转换集中在布局层，调用窗口集中在拷贝适配层。
基址是固定主机标量，动态图绑定留在设备索引和mask中，避免为取得槽基址引入同步。

这是接口契约与CPU地址证据，不是NPU结果。后续硬件入口须覆盖大区域最后槽、
跨页、换槽与零有效行重放；不新增直接BM主存读回，不承诺性能收益。
