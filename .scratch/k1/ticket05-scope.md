## B 完成后，物理存储怎样变化

默认每组为 `{2k, 2k+1}`，owner 为 `2k`。
owner 按 NUMA 映射分配一份，另一成员映射同一块物理存储。
两个进程可以有不同的虚拟地址。

```flow LR
P0 -> 共享副本0: 写前半页
P1 -> 共享副本0: 写后半页
共享副本0 -> D0: 可读完整副本
共享副本0 -> D1: 可读完整副本
```

图中以组 0 为例；默认共 8 组，每组落在对应 NUMA。
4096-token 冷请求有 32 页，默认 P0 写页 0–15、P1 写页 16–31。
每个写者负责完整 token 页的主 KV，分工规则可配置。

| 区域 | 当前份数 | 05 完成后 |
|---|---|---|
| P alive 主 KV | 16 | 8 |
| D alive 主 KV | 16 | 16 |
| P alive Index K | 16 | 16 |
| prefix 主 KV | 16 | 16 |
| prefix Index K | 16 | 16 |

目标向量是 `8 / 16 / 16 / 16 / 16`。
本票减少的是 P alive 主 KV 的物理容量。

## C 具体实现五项行为

| 工作 | 要达到的行为 |
|---|---|
| 建池、映射与注册 | 接通 P 共享、D 私有的布局；注册 8 份 P 副本及其 owner、成员、NUMA。页描述符和容量账本对应实际副本。 |
| prefill 分工写入 | 两个 P 成员按页写共享副本，范围无重叠且覆盖全部有效页。D 通过对应连接读取完整副本。 |
| prefix 路径适配 | op1 fill 由组内两成员按页分担。op3 admit 仍写各 rank 的 prefix，数据源改为本组共享副本。 |
| 就绪合并 | 合并两个写者的完成位图。每份副本只认从第 0 页起连续完成的部分，再汇总所有副本及 Index K 完成进度。 |
| 释放与槽复用 | 每份 P 副本跟踪两个 D 读者。两者都停止读取后才能完成释放确认；两个 P 写者都 free 后才归还共享槽。 |

`ready_tokens` 取 8 份副本的最短连续完成长度，再受 Index K 进度约束。
例如 P1 先写完后半页，前半页仍缺失，就不能提前发布完整就绪。
`free_ack` 和槽复用分别需要读者停止、写者清理的证据。

现有 02 已提供共享池适配器、覆盖位图和读者计数。
当前 SR 仍按每 rank 一份副本、一个读者初始化。
现有会话校验还要求 P/D 共享配置一致。
实施需要让这些接口表达本票的 P 共享、D 私有布局。

## D 怎样验收

| 检查 | 要证明什么 |
|---|---|
| A / B / C / E 与 V1–V10 | 冷请求、命中、后缀、生成、释放和复用继续正确 |
| 跨成员读写 | P 的一个成员读到另一个成员写的哨兵；D 读到对应 peer 之外的 P 成员写的页 |
| 写入与就绪 | 分工完整且无重叠；一个写者提前完成时不会越过未写页 |
| 读者与回收 | 一个 D 读者仍在使用时不能释放；一个 P 写者尚未 free 时不能复用 |
| 注册与物理容量 | P 主 KV 确为 8 份，每 NUMA 一份；区分注册声明与物理页证据 |

复用现有自运行入口，减少模型加载和服务重启。
同一测试需要重复时最多安排两轮，并记录覆盖取舍。
NPU 验收由用户运行，日志保存到 `/home/cryang/log/`。
CPU 通过、NPU 报告通过、用户确认关闭分别记录。

请求释放沿用已有 Main/SR 路径。
服务退出沿用 SGLang 父进程清理路径。
性能复测按现有约定在测试分支安排。
