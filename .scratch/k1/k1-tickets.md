## 1 术语

| 术语 | 含义 |
|---|---|
| 组 k、owner、成员 | 分组 {2k, 2k+1}，k = 0…7，P、D 两侧成员编号一致；owner 是组内第一个 rank（2k），负责分配、绑定 NUMA 和注册该组的共享区域；成员指组内两个 rank |
| 共享池适配器 | 组件实验里的跨进程多参与者共享池：member 0 分配整段，其他成员贡献 0，各进程各自映射 |
| share=0 / share=1 | 适配器开关：每 rank 独立池 / 同组 rank 共享一份 |
| 预重构 | 行为不变、只为让后面的票变薄的改动：覆盖位图、读者计数、多成员会话接口，都先以退化形式落地 |
| 段 | 单份 prefix 池按 NUMA 切成的 8 块，段 k 在 NUMA k，owner 是 rank 2k |
| 起始段 | 一个请求 admit 时第一页落的段，之后按页轮转 |
| 读者分配函数 | load_back 时把命中页分给各 rank 的函数，输入页描述符列表，输出每 rank 的页列表；做成配置 |
| prefix split_read | C100：命中页分给组内各 rank，各 rank 读自己那份进 HBM，all_gather 成全集，各自按原生映射恢复；完成 = 所有 rank 恢复完 |
| numa interleave | C101：admit 分配连续页时在 8 个段之间轮转，使同一请求的页散在各 NUMA；只改分配器选页，不改链式哈希和 place(hash) |
| 全员集合通信 | all-reduce、all_gather 这类“每个 rank 的完成都依赖全部 rank 已进入”的组内通信；broadcast 不算 |
| 覆盖位图 | 协调者按副本记的“哪些页已写完”位图；单写者时等价于原来的连续计数器，双写者时由两个分片的报告合并 |
| 读者计数 | 协调者按副本记的“还有几个读者没停”；计数归零才对 main router 发 free_ack |
| 页驻留证据 | 用 numa_maps 或 move_pages 抽样核对一段内存的页实际落在哪个 NUMA |
| applied / planned | 规划器报告的状态：生产按映射文件启动且逐 rank 注册快照等于映射文件为 applied；只有规划为 planned |
| 暂存区散开 | all_gather 的输出先落一块连续 HBM 缓冲，再按页表拷到各自的 HBM 页 |
| CPU 映射、GPU 注册 | 进程 mmap 共享段供 CPU 拷贝；cudaHostRegister 之后 GPU 才能直接读写它 |
| 哨兵校验、负测试 | 读对方写的那部分并和本地 HBM 里的同一数据比对；负测试指故意拖慢对方写回，看机制是否仍能挡住早读 |
| 基线表 | 票 01 的 perf 子模式产出的那张表；每票原样复现并与票 01 并列 |

## 3 共同规则

1. 每票交付 = 代码 + 验收入口（A / B / C / E 与 V1–V10，按票调整的条目在各票写明）+ perf 子模式基线表 + 证据归档 + 拓扑快照。
2. 基线表与票 01 并列，每段报 n、p50、min、max，T_step 另加 p90、p99。不设性能门槛；变差超过轮间波动要写原因；自动报告的 max ÷ min > 1.5 规则保留，接受与否由用户人工判定，和票 01 一致。
3. 每票重报三项基线遗留：A 比 E 多出的时间及其落点（基线 A 多约 5.2 s，其中 gen 多约 4 s，落在 handoff 附近）；C 的 fill 长尾（基线第 5 轮 781 ms）；每请求 forward 步数（基线记 128）。它们由旁路票 X 定位，各票只重报不处理。
4. 中间版本都要保持第 0 节的“每个中间版本都保持”一行；任何一项退化即票不关闭。
5. 配置化：分组、owner、写分工（P 按页、D 按特征维或按层）、读者分配函数、起始段策略、admit 执行者（并行 / 单 rank）、Index K 写者都做成配置，默认值见各票；不写死“各写一半”。
6. 集合通信只在有序的调度 tick 里发起（M26）；网络接收线程只入队。
7. 拓扑与版本快照沿用票 01 第 6 节，并加：每份共享区域的 owner、成员、会话 id、所在 NUMA、页驻留抽样结果、GPU 注册范围与耗时。
8. fail-stop 不变：证据不齐、断言失败都是票不关闭，不降级。
9. 预重构先行：行为不变的接口与记账改动放在 02b，后面的票只加语义；每票的改动量以一个上下文窗口能装下为限。
10. 票文件里不写分支名和文件路径，那些只留在本文件第 0 节。

## 5 票 01：K1-02a 显式映射启动与页驻留证据

**目标**：让“每份副本放在哪个 NUMA”成为启动时给定、注册时上报、运行时可核对的事实；为后面所有共享区域的放置证据打底。

**改动**

- 生产启动读取 {host, rank, node} 映射文件；每 rank 按映射绑定自己的池；拒绝不合法的映射（节点不存在、rank 重复、缺项）并给出拒绝码。
- 注册上报每份副本的 NUMA 和 owner（此时 owner 就是自己）；规划器报告状态由 planned 改为 applied，定义是逐 rank 注册快照等于映射文件。
- 页驻留抽样：每份副本抽样页实际落在配置的 NUMA；每 NUMA 常驻内存等于两份私有副本。
- 拓扑快照加映射文件、注册快照、驻留抽样结果。

**不变**：副本数 16 / 16 / 16 / 16；池的创建路径不变；main router 的消息、页表、账本不变。

**验收**

- 默认映射（现状的连续映射）：A / B / C / E 与 V1–V10 全过，基线表每段在轮间波动内。
- 另一个合法映射（例如把两个 rank 的副本换到别的节点）：同样全过，驻留抽样跟着映射走，证明映射真的生效而不是恰好等于现状。
- 不合法映射：启动被拒绝，拒绝码正确。

**证据**：applied 报告；两种映射下的驻留抽样；基线表并列。

## 6 票 02：K1-02b 共享池适配器接入（share=0）与记账骨架

**目标**：服务进程通过共享池适配器创建和使用池，share=0，行为与阶段 0 完全相同；把后面票要用的接口和记账先以退化形式落地，用“行为不变”验收接入本身。

**改动**

- 池的创建改走适配器：每 rank 仍是自己池的 owner，成员只有自己；多成员会话接口替换现有两参与者会话，share=0 时成员数等于现状。
- 端口、共享库生命周期、计算图（Graph replay 下的池访问）、请求释放都接到适配器上；关闭路径（正常结束、fail-stop）在多成员会话下仍干净。
- 预重构一：协调者按副本维护覆盖位图，分片报“写完的页”，ready_tokens 由位图算；单写者下结果与原来的连续计数器完全一致，M29 的连续性检查保留。
- 预重构二：协调者按副本维护读者计数，计数归零才对 main router 发 free_ack；现状计数为 1，free_ack 时刻不变。
- 预重构三：注册上报四个副本数和每份副本的 owner、成员列表。

**不变**：副本数 16 / 16 / 16 / 16；每 rank 读写自己那份；main router 的消息、页表、账本不变。

**验收**：A / B / C / E 与 V1–V10 全过；基线表每段在轮间波动内；ready_tokens 和 free_ack 的时间线与阶段 0 一致。

**证据**

1. 关闭路径：正常结束与 fail-stop 各一次，会话、共享段、端口都释放，重启后能再起。
2. 位图与计数器的等价：同一轮里两种算法算出的 ready_tokens 序列逐事件相同。
3. 基线表并列；启动时间记进快照。

**风险**：接入后的启动时间变长；若 share=0 下性能就变了，先在本票解释，不带进后面的票。

## 7 票 03：K1-04 prefix split_read（16 份布局）

**目标**：在每 rank 一份 prefix 的现状上实现分工读加 all_gather（C100），把读路径先做对，让 08 去副本时只换读者分配函数。只依赖 01 基线，可与 01、02 票并行开发。

**做法**

- 读者分配函数：输入命中页的描述符列表，输出每 rank 的页列表。默认轮转：第 i 页给 rank i mod 16；可配；页数不整除时各 rank 补齐到最大值。
- 每 rank 从自己那份 prefix 读分到的页进 HBM 暂存区，按层发起 all_gather（layer-first 下每层一段），all_gather 后按页表散开到各自的 HBM 页；主 KV 仍按原生映射拆回 512 维和 64 维两个缓冲。extend 仍等整段完成，按层流水留阶段 2。
- Index K 同样分法、同样 all_gather，另行恢复。
- 集合通信只在有序调度 tick 里发起；协调者在所有 rank 散开完之后才对 main router ack（op2 对 main router 仍是整段完成）。

**不变**：副本数不变；op1、op3 不变。

**验收与证据**

- B、C 命中，V1 / V3 / V6 / V7；V2 的内容核对改为：all_gather 后的全集与本 rank 私有副本逐 token 一致（这是 08 之后不再有的对照源，本票必须用上）。
- 每 rank 读取字节计数：每页恰好被一个 rank 读一次，总和等于命中页字节。
- ack 时刻晚于最后一个 rank 散开完成。
- 分配函数换成另一种（例如连续块）时结果不变，证明分配是配置而不是写死。

**基线表重点**：T_lb_rank、op2。4K 配置下 op2 约 100 ms 读约 373 MiB，由分段数和控制开销主导，预期本票基本不动 op2；不设门槛。

## 8 票 04：K1-05c dense 读带宽微测

**目标**：补上 dense 本地多读者的 NUMA 饱和点（U6），给 08 的读者分配默认值一个数据依据。不经服务，不阻塞任何票。

**做法**

- 独立小程序：按映射在 8 个 NUMA 各绑一段共享内存，填入同一批页的数据；读者是 GPU 进程，用和 load_back 相同的拷贝接口把页 dense 读进 HBM。
- 档位：1、2、4、16 个读者压同一个段；16 个读者按段交错，每段 2 个。数据量两档：一次 4K 命中的量，和它的 8 倍。每档重复 3 次取中位数。
- 记每读者时间、总带宽、每段带宽。

**产出**：一张表加结论，回填 `../mempool-design/discussion.md` 的 U6；写明“一个段线性到几个读者”“交错相对单段的倍数”。不设门槛。

## 9 票 05：K1-03a P alive 主 KV 共享

**目标**：P 侧 share=1：组 k 两个 rank 共写一份 alive 主 KV，D 的两个 rank 读同一份；每侧 P 从 16 份变 8 份。D 侧仍是 16 份私有副本。

**分组与角色**

| 项 | 内容 |
|---|---|
| 分组 | 组 k = {2k, 2k+1}，k = 0…7；默认 {0,1}、{2,3}…{14,15} |
| owner | rank 2k 分配、绑定 NUMA k、注册副本 k；成员 2k+1 映射同一块物理内存 |
| 写者 | 两个成员按页切（C68）：默认连续两半，rank 2k 写前一半页、2k+1 写后一半，每个 rank 写的都是整页连续段；可配 |
| 读者 | D 的 rank 2k、2k+1 经各自与 P_i 的连接远端 swap_in；P_{2k} 与 P_{2k+1} 注册的是同一块物理内存，所以“D 组 k 读 P 副本 k”自动成立，只是读到的页有一半是对方 P rank 写的 |
| 注册 | R_am(P) = 8，每份带 owner、成员、NUMA；其余三类仍 16 |
| op1 fill 到副本 k | 组内两分片按页分担，各从自己那份 prefix 读进共享副本 |
| op3 admit 从副本 k | 每个 rank 仍对自己那份 prefix 执行 admit，源改为本组的共享副本 |

**就绪与释放**

- 就绪：02b 的覆盖位图由两个分片合并，ready_tokens = 8 份位图从第 0 页起的公共连续长度 × 128，再和各 rank 的 Index K 完成取小；任何一个分片都不能单独伪装成写完。D 的三条件门控形式不变。
- 释放：P alive 副本 k 的读者计数为 2（D 的两个成员）；协调者收齐两个“swap_in 已停”后才发 free_ack；lock_ref 口径不变（C47）。
- 槽复用（V9）：共享副本的存储槽在两个写者都 free 后才归还。

**验收与证据**

- A / B / C / E 与 V1–V10；V4 加“D 读到对方 P rank 写的页”的核对；V9 改为两个写者都 free 后复用。
- 注册快照 R_am(P) = 8，每份有 owner、NUMA、两个成员。
- 哨兵跨进程写读：rank 2k+1 在自己那半页写入模式，rank 2k 经自己的虚拟地址读回比对。
- 常驻内存：P 每 NUMA 等于 1 份副本（阶段 0 是 2 份），总量等于 8 份。
- 写覆盖：两个写者范围并集等于整页且不相交，从配置静态算一次，运行时用字节计数核一次。
- prompt 的 Index K 仍从各 P rank 的 HBM 推送到对应 D rank（C35），本票不碰。

**基线表重点**：T_wt_rank、T_ready、T_tail、T_free；A 的 T_send、T_gate 作参照。

## 10 票 06：K1-03b D alive 主 KV 共享与每步顺序

**目标**：D 侧 share=1：组 k 两个 rank 共写一份 alive 主 KV，每步各写新 token 的一半，下一步读对方写的那一半正确。不依赖 P 侧共享。

**写分工**：两个成员按特征维切（C67）：每层算完，新 token 这一层的 576 维切两半各写一半；可配为按层切。两半是不相交的字节范围。读者是本组两个成员的 swap_in；读者计数为 2。

**每步顺序（默认写法）**

要保证的只有一句：第 t 步两个成员写的全部内容，在任一成员第 t+1 步的任何一次 swap_in 之前已落到 DRAM 并对对方可见。新 token 本步的 KV 不从 DRAM 读，所以读写冲突只跨步。

规则：

1. 写回必须排在本 rank 本层第一次全员集合通信之前。写回和 forward 同流时天然成立；写回走单独的流时，compute stream 在发起本层 attention 输出投影后的 all-reduce 之前等写回的 event。
2. 读取沿用现状，不加任何等待。

依据：全员集合通信里 rank A 的 kernel 完成，意味着对方已进入这次通信，而对方进入之前，它流上排在前面的写回已经完成；A 第 t+1 步的 swap_in 要用本层 top-k 的结果，必然排在 A 第 t 步所有 all-reduce 之后。不加跨进程消息、不加共享内存标志。

放宽版本（备选，T_step 超出轮间波动时启用）：不按层等，在本步最后一次全员集合通信之前等齐本步全部写回。

票内必须验证：

- 现在 D 的写回走哪条流、是 memcpy 还是能入图的写 kernel；单独流且无 event 依赖就加规则 1 的等待。
- 所依赖的通信必须是全员的；broadcast 的完成只依赖根 rank，不能当顺序点。核对本步最后一次集合通信是哪种。
- 跨 GPU 经主存的可见性用哨兵校验实际证明：debug 模式下第 t+1 步开始前，本 rank 从 DRAM 读回 token t 整行，和自己 HBM 里的 token t 比对，不依赖 top-k 是否选中它。
- 负测试：在对方写回流里注入延迟，关掉等待应当失败、打开应当通过。
- 图捕获：写回和 event 在 Graph replay 的捕获范围内，校验在 replay 模式下跑。
- 覆盖检查：每份副本两个写者的范围并集等于整行、两两不相交，静态算一次，运行时字节计数核一次。

**验收与证据**：A / B / C / E 与 V1–V10；V4 加“读对方 rank 写的 token 的最早一步”（第 1 步读位置 prompt_len）；注册快照 R_am(D) = 8；D 每 NUMA 常驻内存等于 1 份副本；哨兵每步校验与负测试通过；replay 模式通过。

**基线表重点**：T_step p50 / p99、T_finish、T_free。

## 11 票 07：K1-05a P alive Index K 单份

**目标**：P alive 的 Index K DRAM 区域改为 1 份（C39），放 NUMA 0，只由 owner 写；顺带把 16 参与者会话（1 个 owner 加 15 个映射者）第一次做出来。prefix 仍是 16 份。

**改动**

- 规划器加这块区域：NUMA 0（第 0 份主 KV 副本所在 NUMA），owner rank 0，16 个进程 CPU 映射，GPU 注册只给 rank 0。
- write_through：Index K 全部页由 rank 0 写；按页分给 rank 1 留作配置项。
- op1 fill 的 Index K 部分：由 rank 0 的分片从自己那份 prefix 读进这块区域。
- op3 admit：每个 rank 从这块区域（CPU 读）把 Index K 页拷进自己那份 prefix。
- ready_tokens 的 Index K 项改为这块区域的完成（rank 0 的报告）。
- 注册 R_ai = 1；账本按 1 份记。D 不读它（C34），prompt 的 Index K 仍从 HBM 推送（C35）。

**验收与证据**：A / B / C / E 与 V1–V10；V2 加 Index K 内容核对（admit 后每 rank 那份 prefix 的 Index K 与区域一致）；注册快照 R_ai = 1 且区域 applied；页驻留在 NUMA 0；只有 rank 0 写（字节计数）；16 参与者会话的创建与关闭干净。

**基线表重点**：T_wt_rank（rank 0 多写 Index K）、T_ready、op1、op3。

## 12 票 08：K1-05b prefix 单份：8 段、numa interleave、按段读者、并行 admit、直接 fill

**目标**：prefix 主 KV 与 Index K 各改 1 份；池分 8 个 NUMA 段并交错分配（C101）；读者按段分配（C100）；admit 并行、fill 直接；规划器补齐并定稿 8 / 8 / 1 / 1 / 1 映射。

### 12.1 布局

| 区域 | 份数 | 段 | owner | 写者 | 读者 | 要 GPU 注册的 rank |
|---|---|---|---|---|---|---|
| prefix 主 KV | 1 | 8 段，段 k 在 NUMA k | rank 2k | admit：页落在段 k 就由组 k 的 owner 写，源是组 k 自己的 alive 副本 k，全程本地 | load_back：组 k 读段 k 的页，组内两成员平分；fill：8 个组各自读全部段，组内两分片按页分担 | 段 k 只需 2k、2k+1 |
| prefix Index K | 1 | 同主 KV，同页号同段（C39） | 同上 | 同上，源是 NUMA 0 的 P alive Index K 区域（票 07） | load_back 同上；fill 由 rank 0 的分片读进 NUMA 0 的区域 | 同上 |

- 所有 16 个进程 CPU 映射全部段；GPU 只注册 load_back 实际碰到的段（组 k 注册段 k）。前提是 fill、admit 沿用阶段 0 的做法，是分片在本进程内做的 DRAM 到 DRAM 拷贝、不经 GPU；若实现走了 GPU 中转，注册范围相应扩大，票内核对。换别的读者分配函数时注册范围随之扩大。
- 共享段在首次触碰前绑定到目标 NUMA（owner 进程 mbind 后再 touch），然后用页驻留证据逐段核对。

### 12.2 页号、分配器、读者分配

- 描述符编码段号和段内偏移；main router 看到的仍是每页 1 个描述符（M37），不知道 NUMA；每个分片都能解析任一段的描述符。
- 协调者的 prefix 分配器维护 8 个空闲表。一个请求 admit n 页时从起始段开始按页轮转，起始段按请求轮转；某段空了就跳过它取最空的段。平衡只在分配这一层保证，不改链式哈希，不改 place(hash)。
- 容量：注册上报总页数 = 8 段之和；main router 的 reserve 只看总量；8 段各自的空闲页要够一次 admit 交错落满；容量参数随单份化重设。
- 读者分配函数切换为按段：按段分成 8 组，组 k 给 rank 2k、2k+1 平分，页数补齐到最大值；其余沿用票 03。

### 12.3 三个操作

- admit（op3）：8 个 owner 并行，各写自己段的页，读本 NUMA 的 alive 副本 k，全部本地；协调者收齐 8 份 ack 后按 parent 先于 child 的顺序 publish。单 rank 版（一个 rank 读自己的副本、写 8 个段）保留为配置项。Index K 部分由各段 owner 从 NUMA 0 的区域读、写进本段。
- fill（op1）：8 个组各自从 8 个段直接读进自己的副本，组内两分片按页分担；每段被 8 个组各读八分之一；8 份进度各自独立进覆盖位图。C40 的“pull 一次再 replicate”留给阶段 1 的远端源。
- load_back（op2）：组 k 读段 k，组内两成员平分，每 NUMA 两个读者；all_gather 与散开同票 03；Index K 同样。

### 12.4 规划器与配置

- 规划器补 prefix 的 8 段：每段 owner、NUMA、CPU 映射者、GPU 注册者；输出定稿的 8 / 8 / 1 / 1 / 1 映射文件和 applied 报告。
- 注册上报：R_pm = R_pi = 1，prefix 总页数、每段页数、每段 owner。

### 12.5 验收与证据

- A / B / C / E 与 V1–V10；V2 改为：冷算 A 时按页另存校验摘要（主 KV 与 Index K 的每页哈希），op1 后 8 份副本、op2 后 HBM 页都与摘要一致。
- 注册快照 = 映射文件（applied）；页驻留逐段核对；每 NUMA 常驻内存 = 1 份 alive 副本 + 本段 prefix（NUMA 0 另加 Index K 区域）。
- 分配日志：同一请求的连续页落在轮转的段上；起始段随请求轮转。
- 读字节计数：load_back 每段读取量相等（补齐后）；fill 每段被读 8 次各八分之一；admit 的写全部落本段（本地比例 100%）。
- 单 writer：admit 每页只有一个写者。
- 账本：prefix 按 1 份记容量，alive 按 8 份；V6 等式用注册值重算。

**基线表重点**：op1、op2、op3、T_lb_rank；预期 op3 因并行 admit 下降，op1 可能变化，op2 基本不动；不设门槛，变差要解释。
