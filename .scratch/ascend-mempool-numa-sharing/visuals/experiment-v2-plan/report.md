**本轮围绕三个问题设计：共享去重是否省时、多个 rank 读取是否争用、分散 NUMA 是否改善性能。**
新增真正的 TP1，所有规模固定数据形状。
主图同时保留独立池、共享池和不同 NUMA 放置。

## A 核心实验矩阵：7 组布局
“TP rank”是访问者，“NUMA node”是主机内存节点。
它们不是同一个概念。
下表的 NUMA 列表按 rank 0、1、2、3 的顺序排列。

| 编号 | 并发 TP 数 | mempool 组织 | 每侧 pool 数 | pool 的目标 NUMA | 回答的问题 |
|---|---:|---|---:|---|---|
| 1-I0 | 1 | rank 0 独占一池 | 1 | [0] | 真正单访问者基线 |
| 2-I0 | 2 | 每 rank 独占一池 | 2 | [0, 0] | 两份副本集中在 NUMA 0 |
| 2-ID | 2 | 每 rank 独占一池 | 2 | [0, 2] | 分散两个 NUMA 的影响 |
| 2-S0 | 2 | 两个 rank 共享一池 | 1 | owner 在 0 | 同 NUMA 下减少一份副本 |
| 4-I0 | 4 | 每 rank 独占一池 | 4 | [0, 0, 0, 0] | 四份副本集中在 NUMA 0 |
| 4-ID | 4 | 每 rank 独占一池 | 4 | [0, 2, 4, 6] | 分散四个 NUMA 的影响 |
| 4-S0 | 4 | 四个 rank 共享一池 | 1 | owner 在 0 | 同 NUMA 下减少三份副本 |

TP1 只有一张消费侧 NPU 执行读写。
它不再用“TP4 组中仅 rank 0 有效”替代。
TP1 的独立与共享结构相同，只跑一次。
共享池保持一份完整分配，先固定放在 NUMA 0。

```callout info 暂定拓扑，等待选择
沿用每侧 NPU 0、1、2、3，TP1/2 取其前缀。
只改变 mempool 的 NUMA 落点。
每 rank 使用固定且互不重叠的可用 CPU 集合。
CPU 集合与池落点分离，整个对照期间保持不变。
P/D 先沿用 10.120.72.31 和 10.120.72.32。
```

固定 NPU 的比较可以观察内存放置的影响。
若同时更换 NPU，应归为另一组部署拓扑实验。
“分散 NUMA”不自动意味着每张 NPU 都访问最近的内存。

## B 所有布局共用的数据与运行条件
| 参数 | 建议固定值 | 原因 |
|---|---|---|
| 执行 | Graph，block_dim=48 | 延续已选的测试方式 |
| KV 行 | 576 个 BF16，即 1152 bytes | 沿用 compact MLA KV |
| 池形状 | 1 层、16 slots、每 slot 65536 行 | 各 TP 数量完全相同 |
| 单池有效容量 | 1.125 GiB，另计 probe 和分配对齐 | 不随 TP 数量改变单池形状 |
| 写入位置 | 单个 slot 内的连续目标区，前后带 guard | 观察大块写入，校验越界 |
| 读请求数 | 1 和 16 | 分开观察低负载与并发压力 |
| 读取 top-k | 每请求恰好 2048 个有效索引 | 不混入 padding-only 工作量 |
| 索引与内容 | 固定种子，各 rank、各模式一致 | 只改变被考察的变量 |
| 层与分片 | 一层，沿 token 行连续分块 | 避免混入 layer owner 或 feature 分片因素 |

读 Graph 的请求维度分别为 1 和 16。
每个子用例的有效数量固定，不用 16 行 padding 模拟真实 batch=1。

相同 TP 数量下，独立池副本数为 TP 数量，共享池副本数为 1。
报告同时列出逻辑容量、实际物理贡献和虚拟地址保留量。
物理分配的对齐空间不计入有效 copy 字节。

## C 大块写入：主实验与等字节对照
**主实验固定一个逻辑任务 L。**
L 取 2048、8192、32768 行，分别为 2.25、9、36 MiB。
每个大小都覆盖 A 面板的 7 组布局。

| 并发 TP 数 | 独立池：每 rank 写入量 | 独立池合计 | 共享池：每 rank 写入量 | 共享池合计 |
|---|---|---|---|---|
| 1 | L | L | 与独立相同 | L |
| 2 | L，写各自的完整副本 | 2L | L/2，写互斥部分 | L |
| 4 | L，写各自的完整副本 | 4L | L/4，写互斥部分 | L |

以 32768 行、TP4 共享池为例：

| rank | 目的行范围 | 行数 |
|---|---|---:|
| 0 | [0, 8192) | 8192 |
| 1 | [8192, 16384) | 8192 |
| 2 | [16384, 24576) | 8192 |
| 3 | [24576, 32768) | 8192 |

四个 rank 同时写入，覆盖完整目标区，目的地址不重叠。
源数据提前在各自 HBM 中准备好，计时仅覆盖 HBM→mempool copy。
分片、metadata 生成、初始化和校验放在计时区外。

```callout info 为什么还需要等字节对照
主实验中的共享池少写副本，实际 copy 量更少。
必须另测相同实际字节量，才能观察池模式的并发效率差异。
```

**等字节对照也固定整组总量为 L。**
独立与共享都让每个 rank 只写 L/N 行。
独立模式写各自池内对应的分片，共享模式写公共池内互斥分片。
这组不要求每个独立池得到完整副本，仅用于 copy 诊断。

它仍覆盖集中 NUMA、分散 NUMA与共享池三种组织。
TP1 两种写实验相同，不重复采集。
这个定义与旧版“每 rank 写 2049 行”的等字节实验不同。
新旧等字节结果不能直接拼在一起。

主要比较：

- 2-I0 对 2-S0、4-I0 对 4-S0：共享去重的组耗时收益。
- 2-I0 对 2-ID、4-I0 对 4-ID：独立池分散 NUMA 的收益。
- 1-I0 对 2-S0、4-S0：固定总量 L，多个 writer 能否缩短时间。
- 相同 N 的等字节结果：减少重复写之外，池组织有何影响。

2049 行保留为分片尾部正确性检查，不扩大主要性能矩阵。

## D sparse 读取：各 rank 读相同索引，每个都得到完整结果
对每个请求，提前生成一组无重复的 2048 个稀疏索引。
从 65536 行历史中抽样，按生成顺序读取。
同一请求在所有 rank 上使用完全相同的索引及顺序。
不同请求可使用不同索引，但跨布局保持一致。

共享模式的多个 rank 读取同一份物理 KV。
独立模式的各 rank 从自己的完整副本读取相同逻辑 KV。
每个 rank 都将全部结果写入自己的 HBM selected buffer。
**读取不按 rank 分成 1/2 或 1/4。**

| 活跃请求数 | 每 rank 的读取量 | TP1 合计 | TP2 合计 | TP4 合计 |
|---|---:|---:|---:|---:|
| 1 | 2.25 MiB | 2.25 MiB | 4.5 MiB | 9 MiB |
| 16 | 36 MiB | 36 MiB | 72 MiB | 144 MiB |

同一 N 下，所有池模式和 NUMA 布局的读取字节量相同。
跨 N 时，总读取量随 N 增长，同时报告耗时与合计有效带宽。
不能仅凭 TP4 比 TP1 慢就认定共享效率差。

**主结果使用随机离散索引。**
每个采样批次切换预生成的索引组，所有 rank 同步切换。
关闭 selected KV 的 HBM 缓存复用，每次都执行 mempool 读取。
这表示应用层 BM miss，不宣称物理缓存处于冷态。
连续索引只作为可单独启用的诊断对照。

```callout info 跨主机读取的暂定范围
主矩阵分别测本地来源、远端来源、各占 1024 行的混合来源。
P 和 D 消费侧分别测量，不同时发起读压力。
另一台主机保持池可用，计时期间不提交设备读写。
混合来源的每请求有效总数仍是 2048。
```

远端独立池同样按 reader 的 rank 选择对应副本。
远端共享池中的所有 reader 指向同一个 owner。
两台主机采用相同目标 NUMA 列表，但分别记录实际分配证据。
若本轮选择只测单机，保留相同 7 组矩阵，只关闭远端和混合来源。

## E NUMA 证据、计时与正确性
**先做小规模预检查，再采集性能。**
自动输出 NPU、CPU 亲和性、pool owner、目标 NUMA 的对应关系。
检查节点 0、2、4、6 在线且可分配，并验证真实映射和读写。
CPU 绑核不能随 mempool 的目标 NUMA 一起移动。

| NUMA 证据状态 | 处理 |
|---|---|
| 实际页或可用驱动查询证实目标落点 | 计入已验证的 NUMA 对照 |
| 证据明确显示落在错误节点 | 该组失败，保存诊断 |
| 驱动映射没有可观测的页计数 | 可保留采样，标为 requested-only / pending |

`HalMemCreate` 日志中的指定 node 作为分配证据保存。
仅有请求参数、成功返回或 `/dev/davinci_manager` 映射，不代表落点已核验。
无法核验时，报告只能比较指定配置，不能宣布 NUMA 因果结论。

**测量建议：3 轮，每轮每用例 20 个采样批次。**
每批 64 次 Graph replay，暖机 5 次，不计入结果。
每批控制同步在计时区外，各 rank 记录设备耗时和主机起止时间。

组耗时使用同机 `max(done) - min(start)`，再除以 64。
每 rank 设备时间单列，不相减不同 NPU 或不同主机的时钟。
组 P50/P95 是批次均摊耗时的分位数，不是服务请求的尾延迟。

记录启动偏差，目标不超过最短设备批次耗时的 10%。
不满足的批次保留为诊断，最多重试 3 次。
仍无法形成并发证据时，该组标为测量无效。
同时保存各轮原始结果，避免仅比较舍入后的 P50。

| 检查 | 方法 |
|---|---|
| 写分片 | 覆盖全集、不相交、边界与 2049 行尾部正确 |
| 写结果 | 所有 writer 完成后，读回完整目标区并检查 guard |
| 稀疏读取 | 每个 rank 的完整输出与 CPU 预期逐元素比对 |
| 数据换代 | 修改内容并切换索引，检查 Graph 未复用旧结果 |
| 跨主机 | 来源、slot、index 均编码进测试 pattern |

校验和发布同步不进入纯 copy 计时区间。
性能采集前后都检查正确性，失败不计作性能结果。

## F 执行规模与最终报告
每个 TP2/TP4 的三种组织按三轮轮换顺序执行：

| 轮次 | 第 1 组 | 第 2 组 | 第 3 组 |
|---|---|---|---|
| 1 | 独立集中 | 共享 | 独立分散 |
| 2 | 共享 | 独立分散 | 独立集中 |
| 3 | 独立分散 | 独立集中 | 共享 |

TP 数量顺序也轮换为 1/2/4、2/4/1、4/1/2。
每组重新建立池，单池容量和数据保持一致。

保留三种读取来源时，每个消费侧有 81 个测量组合。
其中写入主实验 21 个，等字节对照 18 个，读取 42 个。
两侧共 162 个组合；三轮共 486 次组合执行。

只测本地来源时，两侧为 106 个组合；三轮共 318 次执行。
这些计数不含暖机、正确性检查和可选连续索引诊断。

每台主机仍只需一个自运行入口。
入口自动完成预检查、7 组切换、采集、汇总及自身进程清理。
显示整体进度、当前布局、负载、轮次及动态 ETA。
先用小批次实测估时，不预设固定总运行时长。
每个完成组合立即落盘，失败后可按精确配置续跑。
日志保存在 `/home/cryang/log/`，明确失败或待验证状态。
